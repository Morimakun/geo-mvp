## 2. Vision=34 の出所仮説

### 仮説A：AI欄に本当に「34」が書かれている

**条件：**
- AI欄に「34」が明確に見えている
- または、AI欄に「3」と「4」の正の字が連続して見えている

**可能性：** ⭐ 低い（内訳=2 と矛盾するため）

**検証方法：** AI欄を目視確認

---

### 仮説B：非接列の複数行の正の字が「34」に見えている

**根拠：**
- ユーザー提示画像で「非接」列の存在を確認
- 非接列は複数行に正の字が記入されている
- 複数行の正の字を連結すると「34」に見える可能性

**例：**
```
非接列：
  行1：|| （2画）
  行2：1 （1画）
  合計：？

または：

  行1：||| （3画）
  行2：| （1画）
  合計：？
```

**Vision の誤読メカニズム：**
1. Vision が「case_items」region を読むように指示される
2. crop 座標に非接列が含まれている（座標がずれている）
3. Vision が非接列の複数行の正の字を「3」「4」として認識
4. Vision が複数行を連結して「34」と返す

**可能性：** ⭐⭐⭐ 高い

**検証方法：**
- P14 の current crop 画像で非接列が含まれているか確認
- 非接列に「3」「4」に見える正の字があるか確認

---

### 仮説C：非接列の下部合計「14」が「34」に誤読されている

**根拠：**
- ユーザー提示画像で非接列の下部合計が「14」のように見える
- Vision が「14」を「34」と誤読した可能性

**Vision の誤読メカニズム：**
1. crop 座標に非接列の下部合計が含まれている
2. Vision が「1」を「3」と誤読（または「14」の「1」を見落とす）
3. Vision が「4」だけを認識して「4」と返す
4. または、Vision が「1」「4」を逆順に読んで「41」、さらに「3」と混同して「34」と返す

**可能性：** ⭐⭐ 中程度

**検証方法：**
- crop 画像で下部合計の値が見えるか
- 「14」「34」「41」のどれが見えるのか

---

### 仮説D：右側ブロックのテンプレート値（0, 40, 0, 15）が影響している

**根拠：**
- 右側ブロック DM = 40 （テンプレート値）
- crop が右側ブロックも含んでいる場合、Vision が「40」を読むかもしれない
- 「40」が「34」に見える可能性は低い

**可能性：** ⭐ 低い

**検証方法：**
- crop 画像に右側ブロックが含まれているか確認

## 3. Crop 位置の検討

## 5. 判定基準と診断

### 判定A：AI欄由来と確認できる

**条件：**
- AI欄に「34」が明確に見える
- または、AI欄に「3」と「4」の正の字が連続して見える

**判定：** ⭐ 可能性 10%

**理由：**
- 内訳（AU=0, AV=2）と矛盾する
- 「34」を手書きする理由がない（内訳と合わないため）

---

### 判定B：非接列・別列・隣接欄由来の可能性が高い

**条件：**
- AI欄に「34」が見えない
- 非接列に複数行の正の字があり、Vision が誤読した可能性
- または crop に非接列が含まれている

**判定：** ⭐⭐⭐ 可能性 80%

**理由：**
- 内訳（0+2）では「34」が説明できない
- ユーザー提示画像で非接列の存在を確認
- crop 座標がずれている可能性が高い

**最も疑わしい場合：**
```
非接列の正の字：
  行1：||| （3画）
  行2：| （1画）

Vision の見え方：
  行1と行2を連結して「3」「4」と読む
  → 「34」と返す

または：

非接列の下部合計：「14」
Vision が「1」を見落とし、「4」だけ + AI欄の誤読で「34」
```

---

### 判定C：crop 画像だけでは判定不能。ユーザー目視確認が必要

**条件：**
- 画像の解像度が低い
- 複数の列が同時に見えて判別不能
- AI欄の値が曖昧に見える

**判定：** ⭐⭐ 可能性 10%

**理由：**
- 既存の抽出データから推測する限り、誤読の可能性が高い
