# P14 Crop Review Guide - Vision=34の出所特定ガイド

**作成日：** 2026-06-07  
**対象：** P14（page_index=13）イオンモール神戸北  
**目的：** Vision API が読み取った「AI=34」の出所を、作成済みcrop画像を確認することで特定する

---

## 1. 確認すべきcrop画像の優先順位

### 🔴 **最優先確認画像（これだけは必ず確認）**

#### 1️⃣ **p14_ai_area.png** — AI欄周辺
- **確認内容：** AI欄に本当に「34」が見えるか
- **見るべきポイント：**
  - [ ] AI欄（合計欄）に「34」と読める数字があるか
  - [ ] または「3」と「4」が別々に見えるか（正の字か数字か）
  - [ ] または「3」だけ見えるか
  - [ ] まったく違う数字（「14」など）が見えるか
- **判定への影響：** 最大
  - **IF 「34」が見える** → 判定A（AI欄由来・確定）へ
  - **IF 「34」が見えない** → 判定B継続（非接列由来の可能性）

---

#### 2️⃣ **p14_non_contact_column.png** — 非接列周辺
- **確認内容：** 非接列に「34」に見える要素があるか
- **見るべきポイント：**
  - [ ] 「非接」というラベルが見えるか（これが非接列）
  - [ ] 非接列に複数行あるか
  - [ ] 各行に正の字（||||）が記入されているか
  - [ ] 正の字の本数は何本か（各行）
  - [ ] 例：行1に3本、行2に1本、合計4本？
  - [ ] 下部合計欄に何が見えるか（「14」？「34」？「4」？）
- **判定への影響：** 最大
  - **IF 複数行の正の字合計が「34」に見える** → 判定B確定（非接列由来）
  - **IF 下部合計に「14」が見える** → Vision誤読の可能性（「1」を見落とした？）
  - **IF 「非接」列が見えない** → 判定C（確認不能）へ

---

#### 3️⃣ **p14_case_items_current_crop.png** — Vision が実際に見ている範囲
- **確認内容：** Visionのcrop座標に非接列が含まれているか
- **見るべきポイント：**
  - [ ] 画像に「case_items」エリア（AU/AV/AY/AZ/AI）が含まれているか
  - [ ] そのすぐ右に別の列（非接列）が見えるか
  - [ ] 見える場合、その列のラベルは「非接」か
  - [ ] crop範囲が「左側ブロックのみ」か「隣の列も含む」か
- **判定への影響：** 高
  - **IF 非接列が同時に見える** → crop座標がずれている確証
  - **IF 非接列が見えない** → crop座標は正確（別の問題あり）

  - [ ] AY欄：数字が見えるか、空欄か

## 3. P14 AI=34 の出所判定表

| 判定 | 条件 | 根拠 | 推奨アクション |
|------|------|------|----------------|
| **A** | AI欄に「34」が見える | Vision が正しくAI欄を読んでいる | Geo様に確認値「3」の根拠を再確認 |
| **B** | AI欄に「34」が見えない + 非接列に複数行の正の字 + crop に非接列が含まれる | crop座標がずれており、Vision が非接列を読んでいる | crop座標を修正して再試験 |
| **C** | 画像から判別不可 | 解像度不足または複合的な誤読 | ユーザー（Geo様）に原紙目視確認依頼 |

## 5. よくある誤読パターン（参考）

### パターン1：非接列の複数行を合計値として誤読
```
非接列（正の字）:
  行1: ||| （3本）
  行2: | （1本）

Vision の誤読:
  → 「3」と「4」を読む
  → AI欄の値として「34」と返す
```

### パターン2：非接列の下部合計「14」を誤読
```
非接列の下部合計: 14

Vision の誤読:
  → 「1」を見落とす
  → または「14」を「34」と誤認
  → AI欄の値として「34」と返す
```

### パターン3：AI欄とその隣の列を同時に読む
```
AI欄の値:    3
隣の列の値: 4

Vision の誤読:
  → 両者を連結して「34」と返す
```

## 6. 次のステップ

### 確認後の分岐

**判定A（AI欄に「34」が見える）**
1. [ ] Geo様に「実はP14のAI欄に『34』が書かれているのではないか」と確認
2. [ ] 確認値「3」と「34」の差異について原因調査

**判定B（非接列由来が確定）**
1. [ ] Vision APIのcrop座標を修正（非接列を除外）
2. [ ] P14のみ再試験（Vision API再実行は認可）
3. [ ] 正の字カウント改善プロンプト実装

**判定C（判別不能）**
1. [ ] 解像度高いcrop画像を再作成
2. [ ] または Geo様に原紙直接確認依頼

---

## 7. 重要な注意点

- **「34」が見える** = Vision の読取が正確（ただし手書き値の妥当性は別問題）
- **「34」が見えない** = Vision の誤読またはcrop座標の問題
- **非接列の複数行** = 「3」と「4」に見えることあり（正の字の場合）
- **下部合計の「14」** = Vision が視認できればcrop座標がずれている証拠
