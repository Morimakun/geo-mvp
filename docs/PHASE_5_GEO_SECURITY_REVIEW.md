## 3. 検出された主要リスク

### 【高】CSV/数式インジェクション

**リスク内容:**
- CSV出力時に、セルの先頭文字が `=`, `+`, `-`, `@`, タブ、改行 の場合、
  ExcelやGoogle Sheetが**数式として評価**される
- 攻撃者がCSVセルに悪意あるデータ（外部リンク、コマンド等）を仕込むと、
  ファイルを開いた確認者の端末でコード実行される可能性

**該当箇所:**
- 照合結果CSV出力（1152-1197, 1774-1809）：OCR抽出値、CSV由来値
- V2.2参考判定CSV出力（2152-2175）：自動判定結果
- 確認ログCSV出力（2534-2542）：確認者入力値（operator_name, decision_reason）

---

### 【高】XSS（Cross-Site Scripting）

**リスク内容:**
- HTMLレンダリング時に、外部入力やOCR抽出値が**エスケープなしでHTML埋め込まれる**
- JavaScriptコード（`<img onerror="...">`など）が埋め込まれると、
  ブラウザで実行される

**該当箇所:**
- データ比較セクション（1084-1099, 1110-1128）：store_code, staff_name等
- 差分表示（1142-1143）：differences
- 確認ログ表示（複数箇所）

---

### 【中】一時ファイルの放置

**リスク内容:**
- `tempfile.NamedTemporaryFile(delete=False)` で作成した一時ファイルが**削除されない**
- Salesforce CSV（給与・評価に直結する機微データ）が、OSの一時ディレクトリに**平文で蓄積**
- 共有PC や他ユーザーがいる環境では読み取られる可能性

**該当箇所:**
- Tab1: Salesforce CSV読み込み（609-611）
- Tab1: 修正後CSV読み込み（1264-1266）
- Tab2: Salesforce CSV読み込み（1425-1427）
- Tab2: 抽出結果CSV読み込み（1470-1472）

---

### 【中】アップロード上限なし

**リスク内容:**
- PDFアップロード：ファイルサイズ、件数、ページ数に制限がない
- 巨大ファイル / 圧縮爆弾（decompression bomb）でメモリ枯渇 → DoS
- Vision API の有料呼び出しが無制限 → 課金濫用（コストDoS）

**該当箇所:**
- PDF複数アップロード（694-726）
- `extract_items_from_pdf`（extractor.py 146-153）

---

### 【低】情報開示

**リスク内容:**
- エラーメッセージに内部パス・スタックトレース・構造情報を含める
- UI上にトレースバック（837等）を表示

## 4. 今回実装した対策

### 4.1 CSV数式インジェクション対策 ✅

**実装内容:**

```python
def sanitize_csv_cell(value):
    """
    CSVセルの数式インジェクション対策
    危険な先頭文字（=, +, -, @, \t, \r, \n）を検出し、
    先頭にシングルクォート（'）を付与してエスケープ
    """
    if value is None:
        return ""

    text = str(value)

    if text and text[0] in ('=', '+', '-', '@', '\t', '\r', '\n'):
        return "'" + text

    return text
```

**適用箇所:**
- 照合結果CSV出力（Tab1, Tab2）：全セルをサニタイズ
- V2.2参考判定CSV出力：全セルをサニタイズ
- 確認ログCSV出力：全セルをサニタイズ

**効果:**
- Excelが数式として評価しない
- 外部リンク挿入、コマンド実行を防止

### 4.2 一時ファイル削除 ✅

**実装内容:**

```python
tmp_path = None
try:
    with tempfile.NamedTemporaryFile(mode='w', suffix='.csv', delete=False, encoding='utf-8') as tmp:
        df_csv.to_csv(tmp.name, index=False, encoding='utf-8')
        tmp_path = tmp.name

    st.session_state.salesforce_records = load_salesforce_csv(tmp_path)
finally:
    if tmp_path and os.path.exists(tmp_path):
        try:
            os.unlink(tmp_path)
        except Exception:
            pass
```

**適用箇所:**
- Tab1: Salesforce CSV読み込み
- Tab1: 修正後CSV読み込み
- Tab2: Salesforce CSV読み込み
- Tab2: 抽出結果CSV読み込み

**効果:**
- CSVファイルが処理後に必ず削除される
- 顧客データが一時ディレクトリに残存しない

### 4.3 XSS対策（最小限） ✅

**実装内容:**

```python
import html

# 外部入力値をHTMLに埋め込む際にescape
safe_value = html.escape(str(value) if value else "-")
st.markdown(f'<span class="data-value">{safe_value}</span>', unsafe_allow_html=True)
```

**適用箇所:**
- データ比較セクション：store_code, staff_name等のOCR/CSV値
- 差分表示：result.differences

**効果:**
- `<`, `>`, `&`, `"`, `'` が HTML エンティティに変換される
- JavaScriptコードが無効化される

**制限:**
- 静的CSS・固定HTML（83箇所の大半）は対象外
- XSS対策はHTML埋め込みの外部入力値のみに限定

## 5. 今回対応しなかったもの

### 5.1 アップロード制限

**理由:** 実装が重く、デモ用途では即座には必要でない

**本格導入時に必要な対応:**
```
PDF最大ファイルサイズ        → 10MB など上限設定
最大ページ数                  → 100ページ等の制限
Vision API呼び出し上限        → レート制限、クォータ管理
入力検証                      → ファイルタイプ、MIME確認
```

---

### 5.2 認証・権限管理

**理由:** MVP はローカル単一ユーザー想定

**本格導入時に必要な対応:**
```
ユーザー認証          → Salesforce SSO, OAuth等
アクセス制御          → 店舗別、ロール別の権限
操作ログ記録          → 誰が何をしたか追跡可能
監査ログ保存          → コンプライアンス対応
```

---

### 5.3 データ保存・暗号化

**理由:** 現在はCSV出力のみ、DB化は本格導入で

**本格導入時に必要な対応:**
```
暗号化通信            → HTTPS（Streamlit Cloudなど）
保存データ暗号化      → DB上のデータを暗号化
バックアップ管理      → 定期バックアップ、復旧テスト
データ保持期間        → GDPR等の法令対応
```

---

### 5.4 API キー管理

**現状:** `.env` ファイルにハードコード（ローカル開発のみ）

**本格導入時に必要な対応:**
```
環境変数化            → クラウド環境の secrets 管理
キーローテーション    → 定期的な更新
監査ログ              → API キーの利用状況追跡
```

## 6. デモ用途での最低限の前提

本修正は、以下の前提で有効です。

```
✅ ローカルPC上の単一ユーザー利用
✅ 信頼できるユーザーからのアップロード（FAX/CSV）
✅ 短期的なデモ・検証用途
✅ 機微データは最小限（30ページ分）

❌ 複数ユーザー同時利用
❌ クラウド公開（Streamlit Cloud等）
❌ 本番運用
❌ 大量データ処理
```

## 8. クラウド公開時の特別対応

Streamlit Cloud など公開環境への配置を検討する場合は、さらに以下が必須です。

```
□ DDoS対策（CDN, WAF）
□ レート制限（API アクセス）
□ IP ホワイトリスト / VPN
□ 通信の暗号化（TLS 1.2以上）
□ キーの自動ローテーション
□ セキュリティヘッダ設定
□ CORS ポリシー設定
□ 外部侵入検知（IDS/IPS）
```

## 9. 残存リスク

本修正後も、以下のリスクが残存します。

```
【中】アップロード制限なし
    → 対策：ファイルサイズ、ページ数の上限設定

【中】一時ファイルは OS が管理
    → 対策：RAM ディスク利用、ディスク暗号化

【中】複数ユーザー環境での権限分離がない
    → 対策：認証・ACL実装

【低】スタックトレースの情報開示
    → 対策：ユーザー向けはエラーメッセージを隔離

【低】データベース化されていない
    → 対策：本格導入で SQL DB へ移行
```
