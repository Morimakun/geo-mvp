### A. case_items（AU/AV/AY/AZ/AI）の改善

#### 現在の問題

```
v3 精度: 43.3% (13/30)
  - AU: 44% (7/16)
  - AV: 33% (4/12)
  - AY: 20% (1/5)
  - AZ: 0% (0/2)
  - AI: ? (参考値)

理由:
  - AU/AV/AY/AZ は正の字欄だが、数字として読もうとしている
  - AI は数字欄だが、正の字ルール指示の影響を受けている
  - 同じ Prompt で混合処理しているため、混乱している
```

#### 改善案：行分割方式（v5 案）

**現在（v3）**:
```
case_items Prompt:
  AU/AV/AY/AZ/AI を同時に読む

問題:
  - 正の字欄と数字欄を混在
  - Prompt が両方に対応しようとして、どちらも中途半端
```

**改善案（v5）**:
```
分割方式 1: AU 行のみ抽出
  - bounds: AU 行だけに絞る
  - prompt: 正の字専用（短く簡潔）
  - 期待: 単一行なので Vision API も判定しやすい

分割方式 2: AV 行のみ抽出
  - bounds: AV 行だけに絞る
  - prompt: 正の字専用
  - 期待: 同上

分割方式 3: AY 行のみ抽出
  - bounds: AY 行だけに絞る
  - prompt: 正の字専用
  - 期待: 同上

分割方式 4: AZ 行のみ抽出
  - bounds: AZ 行だけに絞る
  - prompt: 正の字専用
  - 期待: 同上

分割方式 5: AI 行のみ抽出
  - bounds: AI 行だけに絞る（合計行）
  - prompt: 数字専用（正の字ではない）
  - 期待: 数字なので精度向上
```

#### リスク評価

```
メリット:
  ✅ 行ごとに最適な Prompt を使える
  ✅ 正の字欄と数字欄を分離
  ✅ Prompt が短く、Vision API 負荷減

デメリット:
  ⚠️ Vision API 呼び出しが 5 倍に増える
  ⚠️ コスト増加（$0.3 → $1.5 / 30 pages）
  ⚠️ 実装複雑化

実施タイミング:
  - Phase 6B v3 が安定後（1-2 週間以降）
  - まず設計だけ作成（この計画の v5 案）
```

### B. AI（合計欄）の専用化

#### 現在の問題

```
AI は合計欄（数字）なのに、正の字ルール指示の影響を受けている

v3 での AI の動き:
  - 時には数字を返す（例: 5, 3, 4）
  - 時には null を返す
  - 時には uncertain を返す
  - 一貫性がない
```

#### 改善案：数字専用 Prompt

**改善前**:
```
case_items Prompt:
  「AU/AV/AY/AZ は正の字
   AI は合計」
  
結果: Vision API が混乱
```

**改善後**:
```
AI 専用 Prompt:
  「AI は合計欄です。手書き数字だけ採用してください。
   空欄は null、不明瞭は uncertain」
   
特徴:
  - 正の字の説明は一切しない
  - 数字の説明だけ
  - 短く（50 語以下）
```

#### 実装方式

```
Option 1: 同じ crop で AI 専用 Prompt を使う
  - case_items 領域から AI 行だけを視覚的に判定
  - AI には「数字専用」で再問い合わせ

Option 2: AI 行の単独 crop を作る
  - AI 行だけを独立した crop として抽出
  - 数字専用 Prompt で読む
```

#### 期待値

```
改善前: AI の一貫性が低い
改善後: AI が確実に数字として読まれる

見込み精度: 60-70%
```

### C. AU/AV/AY/AZ の正の字専用化

#### 正の字読み取りの正しいルール

**ユーザー確認済みルール**:

```
AU/AV/AY/AZ は基本的に正の字欄

読み取りルール:
  - 空欄（手書きなし） → null
  - 横線 1 本 → 1
  - T 字形・7 字形 → 2
  - 3 画分 → 3
  - 4 画分 → 4
  - 完成した正 → 5
  - 手書き 0（明確なもの） → 0（ただし基本的にない）
  - 0 に見えるが不明瞭 → null
  - 不明瞭な線 → uncertain
```

#### 改善案：Prompt 簡潔化

**現在（v3）**:
```
Prompt: 100+ 語
  - BLANK vs ZERO の区別
  - テンプレート値警告
  - 例示複数

結果: v3 でも 44% 程度
```

**改善案（v5）**:
```
Prompt: 50 語以下
  - 正の字のみの説明
  - テンプレート値の警告は削除（AU/AV/AY/AZ には関係ない）
  - 例示は 1-2 個に限定

特徴:
  - Vision API に負荷をかけない
  - 「正の字だけを読む」という指示に集中
```

#### Prompt 案

```
AU/AV/AY/AZ 正の字専用 Prompt 案:

「AU/AV/AY/AZ は正の字で数えます。
  1 = 横線 1 本
  2 = T 字形・7 字形
  5 = 完成した正
  不明瞭 = uncertain
  空欄 = null」

この 50 語で十分。
テンプレート値の警告は不要。
```

#### 期待値

```
改善前: AU 44%, AV 33%, AY 20%, AZ 0%
改善後: AU 60%+, AV 55%+, AY 40%+, AZ 50%+

見込み: 案件系全体で 50%+ へ改善
```
