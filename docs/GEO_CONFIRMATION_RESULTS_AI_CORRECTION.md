```

────────────────────────────────────
34            →  3     十字形＋中段の横棒（3画）をアラビア数字「34」と誤読
```

## 4. Vision API 改善の具体的課題

### 4.1 最優先課題：正の字を数字と区別する

**問題：**
- Vision が「正の字（||||）」を「4」と認識
- 「正の字（||||||||||）」を「10」「34」と認識

**原因：**
- Vision の default OCR が、「縦棒の集合」を「数字」として認識する学習になっている
- プロンプトで「正の字」「正の字（ゲージカウント）」と指定していない

**改善方法：**

```
（現在のプロンプト）
「AI欄の数字を読み取ってください」
→ AI欄に「||||」が見えると「4」と返す

（改善案1：正の字を除外）
「AI欄に、正の字（||||）ではなく、
 アラビア数字（1,2,3...9）が見えたら、その数字を返してください。
 正の字が見える場合は『tally_mark_count=4』のように、
 個数を数えて返してください」

（改善案2：明示的な区別）
「AI欄をよく見てください。
 1) アラビア数字（1,2,3,34,20など）が見える場合：その数字
 2) 正の字（||||）が見える場合：『正の字、画数=○』
 3) 何も見えない場合：『blank』」
```

### 4.2 次優先課題：blank vs 0 の区別

**問題：**
- P12/P28 で「AI欄が空欄」なのに「0」と返す
- クロップ領域が誤っている可能性

**改善方法：**
- クロップ領域確認（case_items の y-offset）
- Vision プロンプトで「セルに何も見えない場合は『blank』」と明示
- 後処理で「blank → uncertain フラグ」に自動変換

### 4.3 実装優先度

| 優先度 | 課題 | 影響範囲 | 実装難度 |
|--------|------|---------|--------|
| 🔴 高 | 正の字→数字誤読の修正 | 13件中 4-5件 | 低（プロンプト修正のみ） |
| 🟠 中 | blank vs 0 区別 | 13件中 2件 + 他ページ | 中（クロップ+プロンプト） |
| 🟡 低 | 内訳抽出精度 | 13件中 3-4件 | 高（クロップ領域見直し） |
