# Phase 6B v3.1: HI=40 再発修正 — 結果報告

**実行日**: 2026-06-06  
**対象**: Page 28 の HI=40 テンプレート値誤読  
**判定**: ❌ **失敗（副作用が大きすぎる）**

---

## 概要

v3 で Page 28 の HI が「40」（テンプレート印字値）と誤読されたため、v3.1 でこれを修正しようとした。

**結果**: HI=40 は消えたが、match_rate が 54.4% → 42.5% に低下したため **採用不可**。

---

## Page 28 の HI=40 の原因

### 構造

existing_support セクションは **3列テーブル**:

| 列 | 内容 | 例 |
|----|------|-----|
| **A（左）** | 項目ラベル | 「1. ネット追加」「2. 電話追加」 |
| **B（中央）** | **テンプレート印字値** | **0**, **40**, **15** など（固定） |
| **C（右）** | **手書き記入欄** | スタッフが実績を記入する場所 |

### Page 28 の状況

- HH（ネット追加）: 右欄 = **空欄** → **null が正しい**
- HI（電話追加）: 右欄 = **空欄** → **null が正しい**（テンプレート「40」は無視すべき）
- HJ（テレビ追加）: 右欄 = **空欄** → **null が正しい**

### v3 で誤読した原因

- bounds (12, 22, 65, 100) がテンプレート値「40」を視界に含めていた
- Prompt が「0 vs 空欄」判定を改善したことで、テンプレート「0」も読み込むようになった
- Vision API が「中央列のテンプレート『40』」と「右側の記入欄」を混同した
- 結果: HI = 40 が返された

---

## v3.1 での修正試行

### 実装内容

**Prompt 強化**:
```
==== BLACKLISTED TEMPLATE VALUES ====

The following numbers appear as PRINTED template values in Column B (middle).
They are NOT handwritten. NEVER return these as extracted values:
  - "0" in Column B
  - "40" in Column B
  - "15" in Column B

If you see "40" anywhere, it is ALWAYS a template value. Return null for that row.
```

### 結果

✅ **Page 28 HI=40 は消えた**:
- v3: HI=40
- v3.1: HI=null

✅ **全30ページで HI=40: 0件**

| 基準 | 結果 | 判定 |

---

## 根本的な問題点

v3.1 の Prompt 修正は **Prompt レベルでの解決不可** であることを証明した。

理由:
1. テンプレート値「40」は crop に見えている
2. Vision API にこれを「読むな」と言っても、テンプレート値が視界にあると判断が曖昧になる
3. 結果として「40 を見たから全て null」という過度な反応になった

---

## 改善方針（v3.2 候補）

### アプローチ A: bounds 調整

```
v3:    (12, 22, 65, 100)   ← テンプレート「40」が見える
v3.2:  (12, 22, 75, 100)   ← 右に寄せて「40」を視界外に
```

**メリット**: Prompt は v3 のままで、crop だけで対応  
**デメリット**: 左側のラベルが見えなくなる可能性  
**見込み**: 検証が必要

### アプローチ B: Page 28 専用対応

現状:
- Page 28 だけ HI=40 が出現（他のページは OK）
- 全 30 ページを修正すると副作用が大きい

→ Page 28 だけに特別な処理を入れるか、v3 の結果で許容するか

### アプローチ C: v3 で許容

```
v3 の状況:
  - match_rate: 54.4%（十分実用的）
  - HI=40: 1件（Page 28 のみ）
  - 副作用: なし

v3.1 の状況:
  - match_rate: 42.5%（不実用的）
  - HI=40: 0件
  - 副作用: 大（existing_support 崩壊）

判定: v3 を使い続け、「Page 28 は要確認」として許容する方が実用的
```
