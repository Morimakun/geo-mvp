### **Phase B: OCR担当者名 → 類似度マッチング**

**目的**: OCR結果を正データマスタと比較し、候補を抽出

**実装項目**:

1. **関数実装**: `find_staff_candidates()`
   ```python
   def find_staff_candidates(
       ocr_name: str,
       staff_master: pd.DataFrame,
       store_code: Optional[str] = None,
       target_date: Optional[str] = None,
       similarity_threshold: float = 0.65
   ) -> List[Dict]:
       """
       OCR結果から担当者候補を検索
       """
   ```

2. **類似度計算**:
   - `difflib.SequenceMatcher` 使用（標準ライブラリ）
   - 複数条件での類似度計算:
     - OCR名 ↔ 正式名
     - OCR名 ↔ カナ
     - OCR名 ↔ aliases
   - 最大スコアを採用

3. **候補ランキング**:
   - スコア降順でソート
   - スコア >= 0.65 のみを返却
   - 最大5候補まで

4. **テスト**:
   - 正常系: 候補複数、候補1名、候補なし
   - 異常系: 空白入力、特殊文字、数字のみ

**実装期間**: 2～3時間  
**テスト用ケース**:
- 「ニス」→ 「ニノミヤ」（類似度0.67）
- 「909」→ 「二宮」カナ「ニノミヤ」（類似度0.72）
- 「xxxx」→ 候補なし

**チェックリスト**:

- [ ] 複数条件（名前/カナ/aliases）対応

- [ ] スコア閾値調整（0.65で妥当か検証）

### **Phase C: 店舗コード・営業日で候補を絞込**

**目的**: 複数候補を、店舗コードと営業日で検証し、確度を上げる

**実装項目**:

1. **有効期間チェック**:
   ```python
   def is_within_active_period(
       target_date: str,
       active_from: str,
       active_to: str
   ) -> bool:
       return active_from <= target_date <= active_to
   ```

2. **店舗コード照合**:
   - PDF店舗コード ↔ 候補の所属店舗コード
   - 一致で確度UP（+0.1点）
   - 不一致で候補から除外するか判断

3. **スコア調整**:
   - 類似度ベーススコア (0.0～1.0)
   - 店舗コード一致ボーナス: +0.1
   - 営業日内: OK、営業日外: 除外
   - 最終スコア = 類似度 + ボーナス

4. **候補の分類**:
   ```
   確定候補: スコア >= 0.85 かつ 候補1名
   複数候補: 候補2名以上
   候補なし: 候補なし
   ```

**実装期間**: 2時間  
**テスト**:
- 有効期間内: OK
- 有効期間外（退職者）: 除外
- 店舗コード一致: スコアUP
- 店舗コード不一致: 判定保留

### **Phase D: 候補をUI表示し、人間が確認・確定**

**目的**: UI上で候補を提示し、人間が最終確認できるようにする

**実装項目**:

1. **結果テーブル拡張**:
   - 既存: `page_number, date, staff_name（OCR）, ...`
   - 追加:
     - `staff_name_ocr` （OCRそのまま）
     - `staff_candidate_1` （候補1名前）
     - `staff_candidate_1_score` （候補1スコア）
     - `staff_candidate_2` （候補2名前）
     - `staff_candidate_2_score` （候補2スコア）
     - `staff_store` （所属店舗）
     - `staff_match_status` （確定/複数/なし）
     - `staff_confirm_status` （人間確認済み/未確認）

2. **詳細確認パネル拡張**:
   - 候補リストを視覚的に表示
   - スコアバーで信頼度を表示
   - 理由（「類似度82%、店舗一致」など）を表示
   - **確認ボタン**: 候補1, 候補2, 手動入力, スキップ

3. **確認・確定の処理**:
   ```python
   def confirm_staff_name(
       page_number: int,
       selected_staff_id: str,
       selected_staff_name: str,
       manual_input: Optional[str] = None
   ) -> None:
       """
       ユーザーが選択した担当者で確定
       """
   ```

4. **ステータス管理**:
   - 確定前: `staff_confirm_status = "未確認"`
   - 確定後: `staff_confirm_status = "人間確認済み"`
   - CSV出力時は確定値を使用

**実装期間**: 4～5時間（UI構築）  
**UI技術**: Streamlit (`st.columns`, `st.button`, `st.selectbox`)

## 🔍 設計上の注意点

### **❌ 避けるべき実装**

1. ❌ OCR結果を正データに存在しない場合は強制的に作成
   - 理由: マスタの整合性が崩れる

2. ❌ 複数候補がある場合、勝手に1つを選ぶ
   - 理由: 人間確認が必須

3. ❌ 有効期間チェックをスキップ
   - 理由: 退職者を誤マッチングする

4. ❌ 店舗コード検証なしに確定
   - 理由: 別店舗の同姓者と混同するリスク

### **✅ 必ず実装すべき事項**

1. ✅ 複数条件での類似度計算（名前、カナ、aliases）
2. ✅ 有効期間の厳密なチェック
3. ✅ 店舗コード照合による確度UP
4. ✅ 人間が確認・確定できるUI
5. ✅ 確認状態をステータスで追跡
