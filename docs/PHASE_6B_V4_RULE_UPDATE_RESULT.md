# Phase 6B v4_rules: 小規模テスト結果

**実行日**: 2026-06-07  
**対象**: 6 ページテスト（P1/P8/P9/P10/P15/P28）  
**判定**: ❌ **Prompt が複雑すぎて、新規オプション・既存対応欄が崩壊**

---

| 領域 | v3 | v4_rules | 変化 | 評価 |
|------|-----|----------|------|------|
| basic_info_header | 100% | 100% | — | ✅ OK |
| basic_info_footer | 91.7% | 91.7% | — | ✅ OK |
| case_items | 41.3% | 36.7% | -4.6pt | ⚠️ 微悪化 |

## 詳細分析

### case_items（AU/AV/AY/AZ/AI）

```
v3:      11/30 success (41.3%)
v4:      11/30 success (36.7%)  ← 数字は同じだが uncertain の扱いが変わった

主な変化：
  - P1 AU: 4 → uncertain ？？
  - P9 AI: 2 → uncertain
  - P10 AI: 2 → 0  （AI は正しく 0 を返した）
```

**評価**: 微悪化、ただし方向は正しい。「0 を見たら uncertain」という指示が機能している可能性がある。

### existing_support（HH/HI/HJ）

```
v3:   4/90 success (4.4%)
v4:   0/90 success (0%)  ← すべて null に！
```

**原因推測**:
- Prompt が長すぎて（700語以上）、Vision API が後半の指示を読み切れていない
- テンプレート値「40」の警告が強すぎて、「40 を見たら絶対に null」と解釈された
- 結果：すべてのページで HH/HI/HJ が null に変わった

### new_options（GS/GT/GU）

```
v3:  16/90 success (17.8%)
v4:   0/90 success (0%)  ← すべて null に！（P8 GT だけ uncertain）
```

**原因推測**:
- P8 特別注記「GS/GU は空欄」の指示が、全ページに適用されてしまった可能性
- あるいは Prompt 全体が複雑すぎて、Vision API が「よくわからないなら null」と判定

---

## 問題の根本

v4_rules の Prompt は以下の理由で失敗した：

1. **Prompt が長すぎた（700+ 語）**
   - existing_support: 250+ 語
   - new_options: 200+ 語
   - Vision API が「後ろの方の複雑な指示」を読み切れていない可能性

2. **テンプレート値警告が過度だった**
   - v3.1 で失敗した教訓が活きなかった
   - 「40 を見たら絶対に null」と言い過ぎ

3. **特別ケース指示が全体に影響**
   - P8 GS/GU は空欄「という注記が、他のページにも影響した可能性

---

## v3.1 との比較（教訓）

| 試み | 問題 | 結果 |
|------|------|------|
| **v3.1** | HI=40 を fix するため「40 は絶対に値にしない」と prompt で強調 | existing_support 全体が崩壊（27→4） |
| **v4** | HI=40 を含む複雑な prompt で修正 | existing_support 全体が崩壊（4→0） |

**教訓**: Prompt レベルでの修正は「全体に波及するリスク」が高い。

---

## 推奨対応

### 案 A: v3 に戻す（推奨）

```
理由：
  - v3 は existing_support 4/90 でも「失敗」ではない
  - v4 は 0/90 なので、確実に悪化
  - Phase 4b での比較は v3 で十分実用的

判定: v3 を本採用のままにする
```

### 案 B: v4_rules を簡潔に修正

```
修正内容：
  - Prompt を 300 語以下に削減
  - テンプレート値警告をあいまいに
  - P8 特別ケースを削除（一般化）

リスク:
  - さらに修正を繰り返すと時間コスト高い
  - Vision API の「判読力の限界」は変わらない
```

### 案 C: bounds 調整で解決（将来）

```
理由：
  - 「Prompt が理解できない」のではなく「Crop が悪い」可能性
  - existing_support の bounds を調整して、テンプレート列「40」を視界外に

実行：
  - v3.2 として bounds のみ修正
  - テンプレート値を視界から除外
  - 同じ Prompt で再テスト
```

---

## 結論

### ❌ v4_rules は採用しない

理由：
- existing_support: 4% → 0%（改悪）
- new_options: 17.8% → 0%（改悪）
- 全体的に「複雑なプロンプトが逆効果」を示唆

### ✅ v3 を本採用のままにする

理由：
- match_rate 54.4%（実用的）
- existing_support は低いが、MVP 対象外の現段階では許容
- 案件系の改善は別途アプローチ（Prompt ではなく bounds 調整）

### 🔮 将来の改善案：v3.2 → bounds 調整

```
実施時期: Phase 6B v3 安定後
内容：
  - Page 28 HI=40 の問題を「bounds 調整」で解決
  - テンプレート列を視界外に寄せる
  - Prompt は v3 のままキープ
```
