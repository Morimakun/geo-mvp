## ページ別 raw_response 詳細分析

### P24 六甲道（v3=7, user=2, V2.1=None）

**失敗分類：A+C（プロンプト厳格すぎ＋セル誤認識）**

#### Visionが見えていたもの

> 「該当セルにはチェックマーク（レ点・斜め線）のような記号が **2つ** 書かれているように見える」

#### 重要な発見

- Vision は **「2つの記号」** を認識している
- ユーザー目視解釈も **2**
- つまり Vision は正しい数を見ている可能性が高い
- しかし「正の字でもアラビア数字でも空欄でもない形状」と分類し、uncertain に逃げた

#### uncertainにした理由

- プロンプトが「記入形式A/B/C」の3択を強制している
- チェックマーク状の記号は A/B/C のどれにも該当しないと Vision が判断
- 結果として uncertain を返した

#### セル誤認識の問題

- raw_text: 「⑯ SBAir ユーザー数（HT/Mz）」の「紹介」行を読んでいる
- AI合計欄ではなく、別の行を見ている可能性がある

---

### P14 イオンモール神戸北（v3=34, user=3, V2.1=None）

**失敗分類：B+C（画像品質不足＋セル誤認識）**

#### Visionが見えていたもの

> 「画像の解像度が非常に低く、AI合計欄（合計数字記入行）のセル内容が判別できません」  
> 「エリア外数の行の紹介・再掲欄は黒く塗りつぶされている」  
> 「その他のセルも空欄またはかすれて見えます」

#### 重要な発見

- 4倍スケール（≈300dpi）にもかかわらず **「解像度が非常に低い」** と主張
- テーブル構造は認識できるが、セル内の手書き文字が読めないと判断
- **黒塗り（個人情報マスク）** が大きな障害

#### uncertainにした理由

- セル内容が判別不可
- 黒塗り部分と内容の区別がつかない
- 高解像度画像での再提出を推奨している（= 現画像では不十分と判断）

#### セル誤認識の問題

- 「エリア外数」の行を見ている → AI合計行ではない可能性

---

### P11 深江橋（v3=20, user=2, V2.1=None）

**失敗分類：A（プロンプト厳格すぎ）**

#### ★★★ 最重要発見 ★★★

raw_text に以下の記述がある：

> 「該当セルには **『正』の字が記入されているように見えます** 」  
> 「 **『正』（5画完成形）と読み取れる記号** と、その左に **『一』のような横棒** が見えます」

#### Vision は正の字を見ている

- Vision は明確に「正の字」と言及している
- 「正（5画完成形）」＋「一（1画）」= **6画** と読める可能性を示唆
- ユーザー目視では **2**（2画の正の字）

しかし最終判定で：

> 「画像の該当セルは **黒塗り（黒く塗りつぶされている）部分が多く** 、読み取りが困難です」

と retreatして uncertain を返した。

#### uncertainにした理由

- **黒マスクが原因**。正の字が見えていたのに、黒塗り領域との重なりで確信が持てなくなった
- プロンプトの「明確に判定できない場合はuncertainと返してください」が裏目に出た

#### セル誤認識の問題

- 「⑱未導入物件数（MT）の紹介欄」を読んでいる → AI合計行ではない

---

### P12 広畑（v3=0, user=1, V2.1=blank）

**失敗分類：C+D（セル特定失敗＋crop範囲過大）**

#### Visionが見えていたもの

> 複数行を一括で読み取り、JSON配列で返却  
> すべての行を「blank」と判定

#### 重要な発見

- Vision は **単一セルではなく複数行を一括読み取り** した
- JSON 配列の最初の要素「モバイルユーザー数(HT/Mz) 合計」→ blank を取得
- **AI合計セルではない行を読んでいる**

#### blank判定の理由

- 「合計欄に明確な記入が確認できない」
- ユーザー目視では **1**（1画の正の字 = 横棒1本）だが、Vision はこれを認識できなかった
- 1画（横棒のみ）は罫線との区別が困難

#### 正規化の問題

- JSON 配列の最初の要素だけを `re.search(r'\{[^{}]*\}')` で取得
- 配列全体ではなく先頭の1要素だけが結果に使用された
- これは正規化ロジックの問題でもある

---

### P28 宝殿（v3=0, user=0, V2.1=None）

**失敗分類：A（プロンプト厳格すぎ）**

#### Visionが見えていたもの

> 「画像が非常に不鮮明」  
> 「各行の産出欄はいずれも **空欄または記入内容が確認できません** 」  
> 「空欄の可能性が高い」

#### 重要な発見

- Vision は **「空欄の可能性が高い」** と明言している
- これは正解（ユーザー目視=0、v3=0）
- しかし uncertain を返した（blank ではなく）

#### uncertainにした理由

- 「画像が非常に不鮮明」→ 確信が持てない → uncertain
- プロンプトの「明確に判定できない場合はuncertainと返してください」が直接の原因
- **blank と返すべき場面で uncertain に逃げている**

## 失敗原因の横断分析

### 1. 失敗分類の集計

| 分類 | 該当ページ | 説明 |
|------|-----------|------|
| **A: プロンプト厳格すぎ** | P24, P11, P28 | 値が見えているのにuncertainに逃げた |
| **B: 画像品質不足** | P14 | 4xスケールでも「低解像度」と主張 |
| **C: セル特定失敗** | P24, P14, P11, P12 | AI合計行ではなく別の行を読んでいる |
| **D: crop範囲過大** | P12 | 複数行を一括読みしてしまった |
| **E: 正規化処理の問題** | P12 | JSON配列の先頭要素のみ取得 |

### 2. 根本原因の優先順位

```
1位：セル特定失敗（5ページ中4ページ）
  → Vision が AI合計行を正しく特定できていない
  → 別の行（SBAir/未導入物件数/モバイルユーザー数/エリア外数等）を読んでいる

2位：プロンプト厳格すぎ（5ページ中3ページ）
  → 「uncertain」に逃げやすすぎる
  → P11: 正の字が見えているのに retreat
  → P28: 空欄と分かっているのに retreat

3位：黒マスク（個人情報マスク）の影響（5ページ中3ページ）
  → P14/P11/P12 で黒塗りが判読を妨害
  → 特にP11では正の字が見えていたのに黒塗りで確信喪失

4位：正規化処理（1ページ）
  → P12: JSON配列→先頭要素のみ取得の問題
```

### 3. 正規化処理の問題点

| ページ | raw_responseに正しい値はあったか | 正規化で失われたか |
|--------|--------------------------------|-------------------|
| P24 | No（uncertain のみ） | No |
| P14 | No（uncertain のみ） | No |
| P11 | **一部あり**（正の字5画+横棒1画の記述）だが最終値はuncertain | No（最終JSON値がuncertain） |
| P12 | No（blank のみ）だがJSON配列の問題あり | **Yes**（配列先頭のみ取得） |
| P28 | No（uncertain のみ）だが「空欄の可能性が高い」の記述あり | No（最終JSON値がuncertain） |

**結論：正規化処理の問題は P12 のみ。主因はプロンプトとセル特定。**

## V2.2 方針案の評価

### 案1：プロンプトを緩める

**効果予測：P28（確実）、P11（高確率）、P24（中確率）**

```
変更内容：
- 「明確に判定できない場合はuncertainと返してください」を削除
- 代わりに「もっとも可能性の高い値を推定して返す。ただしconfidenceを付ける」に変更
- 「不鮮明でも、見えている痕跡から最善の推定を行う」を追加
```

**評価：** ⚠️ 効果はあるが、セル特定問題は解決しない

### 案2：セル指定を強化する

**効果予測：P24（高）、P14（高）、P11（高）、P12（高）**

```
変更内容：
- 「このcrop画像にはAI合計行が1行だけ含まれています」を明記
- 「灰色/網掛けの行がAI合計行です」を追加
- 「紹介行・再掲行は読まないでください」を追加
- 「1つのセルだけを読んで、1つの値だけを返してください」を追加
```

**評価：** ✅ **最も効果的**。4/5ページでセル誤認識が原因

### 案3：出力形式を変える

**効果予測：P11（高）、P28（高）**

```json
{
  "visible": true/false,
  "mark_count": 2,
  "mark_type": "tally_stroke",
  "estimated_value": 2,
  "confidence": "low",
  "reason": "2画の正の字に見える"
}
```

**評価：** ⚠️ 有用だが、セル特定問題は解決しない

### 案4：AIセルだけ＋ラベル付きcropを作る

**効果予測：P24（高）、P14（高）、P11（中）、P12（高）**

```
変更内容：
- Pattern B（1071×842px）が広すぎる
- AI合計行の1セル＋上下の行ラベルだけを含む極小cropに変更
- 例：200×100px 程度のセル1つ分
```

**評価：** ✅ セル特定問題を物理的に解消。ただしcrop座標の精密化が必要

### 案5：AI欄は自動確定対象から外し、要確認に落とす

**効果予測：全ページ（確実）**

```
変更内容：
- AI合計欄の自動確定を諦める
- すべて「要確認」として扱い、人間が目視で確認
- デモでは「AI欄は確認支援対象」と説明
```

**評価：** これは現時点での実質的なフォールバック。改善が行き詰まった場合の最終手段。

## V2.2 推奨方針

### 最優先：案2＋案1 の併用

**理由：**

1. **セル特定が最大の問題**（4/5ページで発生）
   - 案2 でプロンプトにセル指定を追加
   - 「灰色/網掛けの合計行を1行だけ読む」を明記

2. **プロンプト厳格すぎが2番目の問題**（3/5ページで発生）
   - 案1 で「uncertain」逃げを抑制
   - 「最善の推定を返し、confidenceで不確実性を表現」に変更

3. **P11 の正の字認識は有望**
   - Vision は正の字を見る能力がある
   - プロンプト緩和とセル指定強化で改善可能

### 次点：案4 の検討

- 案2+案1で改善が見られない場合のみ
- crop座標の精密化コストが高い

### 保留：案5

- V2.2でも改善しない場合のフォールバック
- デモへの影響は小さい（「要確認」戦略と整合的）

## P11 の特別な発見について

P11 深江橋の raw_text は、V2.1 の中で最も重要な発見を含む：

```
「該当セルには『正』の字が記入されているように見えます」
「『正』（5画完成形）と読み取れる記号と、その左に『一』のような横棒が見えます」
```

これは以下を意味する：

1. **Vision は正の字を認識する能力がある**
2. **正の字プロンプト（V2改善版）は機能している**

V2.2 で以下を改善すれば、P11 は高確率で正解を返す：
- セル指定（⑱未導入物件数ではなくAI合計行を読む）
- プロンプト緩和（黒マスクがあっても推定値を返す）
