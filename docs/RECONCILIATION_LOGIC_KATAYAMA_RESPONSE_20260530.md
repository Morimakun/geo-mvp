## 🔴 重要な変更点

### 旧方針（非推奨）

PDF側から読み取った以下をSalesforce CSV側と直接照合する。

- 日報DataNo
- タブレットNo
- 担当者名

**この方針は一旦停止**

理由：Salesforce CSVに該当列を出力できないため。

---

### 新方針（2026-05-30 確定）

#### Salesforce CSVに出力できない項目

```
❌ 日報DataNo
❌ タブレットNo
❌ 担当者名
```

#### 照合の主軸

```
✅ 日付
✅ 取扱店コード（CSV側）
✅ 集計欄・商品別数字（ただし対応待ち）

重要：PDF店舗名 × CSV取扱店コードの対応表を作成する必要あり
  → store_code_mapping_draft.csv として STAGE 2 で対応予定
```

#### PDF側のDataNo / TabNo / 担当者名の扱い（2026-06-02 電話確認反映）

```
📍 日報DataNo：帳票確認補助情報として保持（照合キーとしては未使用）
📍 TabNo：店舗確認補助情報として保持（スタッフ特定キーではない）
📍 担当者名：候補提示情報として保持（直接照合には非使用）
❌ これらのいずれも CSV直接照合キーとしては使用しない
```

**スタッフ・店舗について（2026-06-02 電話確認反映）**

| 項目 | 内容 | 注記 |
|-----|------|------|
| **スタッフの配置** | 店舗固定ではなくスポット入店の場合がある | 所属店舗だけで担当者候補を限定してはいけない |
| **TabNo の紐づき** | スタッフではなく**店舗に紐づく** | TabNo からスタッフを特定できない |
| **担当者特定** | 所属店舗スタッフだけで限定すると、スポット入店に対応できない | 店舗に応じた候補提示が必要（今後の工夫が必須） |
| **担当者名リスト** | ジオ側で共有いただける可能性あり | STAGE 2 で staff_name_master.csv として作成予定 |

## 📋 照合単位（2026-06-02 電話確認反映）

### 基本単位

```
✅ PDF帳票1ページ = Salesforce CSV 1行 で対応

複数ページの帳票は複数行のCSVと照合する
```

### 照合フロー

1. PDFを1ページずつ読み込み
2. 抽出された日付と店舗コードで CSV側の該当行を検索
3. 「一致」「不一致」「要確認」を判定
4. 複数ページ時は逐次処理
