## 0. 先方に聞く前の自己再確認結果（Step 2）

質問する前に、こちら側のミスでないことを以下の通り再確認した。

| 確認観点 | 方法 | 結果 |

| 店舗/イベント2行構成が絡んでいないか | 6/27の重複2店舗（鶴見・枚方）のCSV2行を個別に確認 | **CSV行1=店舗分（転記シートと一致）、行2=イベント分**の構造を確認。不一致3店（大久保・くモ・大日）はCSV1行のみで、2行構成は絡んでいない |
| PDFページの見落としがないか | 全66ページのヘッダー帯を目視で再確認 | 不一致3店の6/27帳票はP11（大久保・新）、P24（くモ・新）、P10（大日・旧）の各1枚のみ。イベント帳票は見当たらない |
| 店舗コードで検索しても同じか | 転記シートV3のフルコードとCSV col1をコードで結合 | 同じ結果（店舗名でなくコード結合で実施済み） |
| 新旧帳票混在による分類ミスではないか | 大日（旧帳票店）の転記シートを確認 | 旧帳票の内容も転記シートに転記されており、転記自体は行われている。分類ミスではない |

**再確認で得られた追加の事実：**
- 不一致3件はいずれも「**新規紹介だけがCSV側で増えている**」（既存側は3件とも一致）
  → 単純な読み間違いや列ズレでは説明できず、**転記後にSalesforce側へ新規分が追加計上された**形跡
- **お声がけ総数（CZ合計欄対応）は3日間・全店で0** → 今回データではCZ側の照合検証は実質できない
- 船橋は転記シートに3日分とも値があり（紹介6/6/8）、CSVとも一致 → **帳票そのものはジオに届いている**

## A. 6/27 不一致3件の根拠表

| 項目 | ① 明石大久保 | ② くずはモール | ③ イオンモール大日 |
|------|------------|--------------|------------------|
| 日付 | 2026/6/27 | 2026/6/27 | 2026/6/27 |
| 店舗コード | AU1KC400012 | AU1KC901225 | AU1KC490237 |
| PDFページ | P11（新帳票・区分1店舗） | P24（新帳票・区分1店舗） | P10（**旧帳票**） |
| 転記シート：紹介合計（内訳） | **0**（新規0／既存0） | **7**（新規4／既存3） | **4**（新規1／既存3） |
| CSV：紹介総数（内訳） | **2**（新規2／既存0） | **13**（新規10／既存3） | **6**（新規3／既存3） |
| 差分 | +2 | +6 | +2 |
| 不一致項目 | 紹介総数（**新規のみ**） | 紹介総数（**新規のみ**。既存は3で一致） | 紹介総数（**新規のみ**。既存は3で一致） |
| お声がけ総数 | 両方0（一致） | 両方0（一致） | 両方0（一致） |

**想定される原因候補（3件共通）：**
1. 帳票提出後の追加実績をSalesforce側に直接入力（＝再送帳票なし・CSVのみ更新）
2. 再送帳票（変更あり）が存在するがPDF束・転記シートに反映されていない
3. 転記のタイミング差（転記が先、CSVエクスポートが後）
4. 別スタッフ・別紙の帳票が存在する（大日は6/25の旧帳票に名前2名併記の例あり）
5. 転記漏れ（ただし3件とも「新規のみ」で系統的なため、単純ミスの可能性は低め）

**確認文案（下書き）：**
> 6月27日分について、帳票の合計欄とSalesforce CSVの紹介総数が異なる店舗が3店ございました（明石大久保：帳票0・CSV2／くずはモール：帳票7・CSV13／イオンモール大日：帳票4・CSV6。いずれも新規分のみの差で、既存分は一致しています）。
> このような差は、帳票提出後にSalesforce側へ追加入力されるケースがある、という理解でよろしいでしょうか。もし再送帳票や別紙が存在する場合は、その運用も教えていただけますと幸いです。

## B. イベント帳票あり／CSV1行のみの根拠表

| 項目 | ① イオンモール堺北花田 | ② イオンモール神戸北 |
|------|---------------------|-------------------|
| 日付 | 2026/6/27 | 2026/6/27 |
| 店舗コード | AU1KB830201 | AU1K4050139 |
| 店舗帳票 | あり（P5・区分1） | あり（P25・区分1・提出1） |
| イベント帳票 | **あり（P6・区分2**・スタッフ名に訂正線） | **あり（P26・区分2**・提出1） |
| CSV行数 | **1行のみ**（紹介総数0） | **1行のみ**（紹介総数1） |
| 転記シート | 1シート（店舗分・紹介0でCSVと一致） | 1シート（店舗分・紹介1でCSVと一致） |

**参考（対照ケース）：** 同日の鶴見緑地・ニトリモール枚方は「店舗＋イベント」2枚提出でCSVも2行（行1=店舗分・行2=イベント分）であることを数値で確認済み。

**想定される原因候補：**
1. イベント帳票の実績がゼロだった場合、Salesforce側にイベント行を作らない運用
2. イベント分が店舗分の行に合算されている
3. イベント帳票は提出されたがSalesforce未入力（入力待ち・入力漏れ）
4. PDF側の区分記入（2 イベント）が実態と異なる（誤記入）

**確認文案（下書き）：**
> 6月27日分では、鶴見緑地様とニトリモール枚方様は「店舗」「イベント」の帳票2枚に対しCSVも2行出力されており、対応関係がよく分かりました。
> 一方、堺北花田様と神戸北様も「イベント」に丸の付いた帳票が2枚目としてございましたが、CSVは1行のみでした。イベント実績がない場合はCSV行を作成しない運用など、イベント分の計上ルールを教えていただけますと幸いです。
