# AI（案件合計）欄 突合差分 ジオ様確認依頼

**作成日：** 2026-06-07
**対象：** Phase 6B v3 突合テスト（30ページ全件）
**目的：** PDF合計欄とSalesforce CSVの差分について、定義・マッピングを確定する

---

## 1. 概要

PDF（FAX日報）とSalesforce CSVの突合テストを実施したところ、**AI（案件合計）欄で13件の差分**が確認されました。

重要な点：

- ✅ **OCR自体はAI合計欄を100%読み取れています**（数字は正しく抽出できている）
- ⚠️ ただし、**PDFの合計欄とCSVの対応列・定義が完全に一致しているか未確認**です
- 📌 特に、**PDFのAI値とPDF内訳（AU+AV+AY+AZ）の合計が一致しないケースが12/13件**あり、AI欄の定義そのものの確認が必要です

この差分が「実際のデータ差分（ツールが正しく検出）」なのか「定義・マッピングのズレ」なのかを切り分けるため、ジオ様に確認をお願いしたく存じます。

---

## 2. 確認したい背景

### なぜ確認が必要か

AI（案件合計）欄について、以下の根本的な疑問があります：

| 観点 | 現状 | 確認したいこと |
|------|------|--------------|
| **PDF側の定義** | AI=合計欄。だが内訳合計と不一致 | AIは何の合計か？手書き手入力か？ |
| **CSV側の対応列** | 対応表PDFで列35（コードAI）と確定済み。列名（日本語）のみ空欄 | この対応列・定義で合っているか |
| **集計期間** | PDF=当日想定、CSV=不明 | 期間定義は一致しているか |

> 📌 **事前照合済み：** 受領済み対応表PDFと現在の実装マッピングを照合した結果、**PDFのAI欄はCSV列番号35（コードAI）に対応**することを確認しました（`docs/AI_TOTAL_MAPPING_REFERENCE_CHECK.md`）。よって本依頼は「どの列か」を尋ねるものではなく、「**この対応列・定義で合っているか**」を確認するものです。

### 切り分けたい2つの可能性

```
差分13件
  ├─ ① 実データ差分（ツールが正しく検出） → 不一致として報告でOK
  └─ ② 定義・マッピングのズレ           → マッピング修正が必要
```

この確認により、**MVPの照合ルールを確定**できます。

## 5. ジオ様への確認事項

### A. PDFのAI欄は何の合計ですか？

PDFの「合計（数字で記入）」欄について：

- [ ] **AU + AV + AY + AZ の合計**ですか？（案件4種の合計）
- [ ] それ以外の項目（eo光・フレッツ光等の内訳）も含みますか？
- [ ] スタッフが**手書きで自由に記入**する合計ですか？
- [ ] **自動計算ではなく手入力**ですか？

> 📌 **背景：** PDFのAI値と内訳（AU+AV+AY+AZ）合計が13件中12件で一致しません。例えばP11（深江橋）は内訳=0なのにAI=20です。AI欄が内訳の合計ではない、別の意味を持つ可能性があります。

---

### B. CSVのAI対応列（列35）はこの理解で合っていますか？

いただいた対応表PDFでは、PDFの「AI（案件合計）」はCSVの**列番号35（列コードAI）**に対応する、と理解しております。

- [ ] この対応列（**列35＝AI**）で合っていますか？
- [ ] 対応表PDFでは「合計」に**列35(AI)と列104(CZ)の2列**が紐付いていますが、この2列の使い分けは何ですか？（HT/Mz と MT の区分など）
- [ ] 列35(AI)の正式な**列名・集計定義**を教えてください（対応表PDFでは列名が空欄でした）

> 📌 **背景：** 受領済み対応表PDFと実装マッピングを照合したところ、**列コード・列番号は確定済み（AI=列35）**で、両者にズレはありませんでした。不明なのは「列の日本語名称」と「AI(35)/CZ(104)の使い分け」のみです。よって本項目は「どの列か」ではなく「**この対応で合っているか**」の確認です。

---

### C. 集計期間は一致していますか？

PDFとCSVの集計対象期間について：

- [ ] PDFは**当日分**の数字ですか？
- [ ] CSVは**当日分**の数字ですか？
- [ ] Salesforce側は更新タイミングで数字がズレますか？
- [ ] 日次／期間／累計が混在していませんか？

> 📌 **背景：** P2・P10（イオンモール大日）はPDF=0に対しCSV=2です。PDFが空欄でもCSVに値があるのは、集計期間や記録タイミングのズレが原因の可能性があります。

---

### D. PDF原紙の数字を確認してください

優先5ページの原紙について、実際の記入内容を確認してください：

- [ ] **P14（イオンモール神戸北）** の合計欄は本当に「**34**」ですか？
- [ ] **P11（深江橋）** の合計欄は本当に「**20**」ですか？
- [ ] **P24（六甲道）** の合計欄は本当に「**7**」ですか？
- [ ] **P12（広畑）** のAI欄は本当に「**0または空欄**」ですか？
- [ ] **P28（宝殿）** のAI欄は本当に「**0または空欄**」ですか？

> 📌 **背景：** これにより「OCR読取は正しいが定義が違う」のか「OCR読取自体に誤りがある」のかを切り分けられます。

---

### E. 不一致は実差分として扱うべきですか？

突合ルールの確定について：

- [ ] PDFとCSVが違う場合、**どちらを正**としますか？
- [ ] ツールは「**不一致**」として報告すればよいですか？
- [ ] **自動修正は不要**でよいですか？（人による確認に回す運用でよいか）

> 📌 **背景：** MVPでは「ツールは差分を検出して報告し、最終判断は人が行う」設計を想定しています。この方針でよいかご確認ください。
