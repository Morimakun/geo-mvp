| ページ | V2.2 | CSV | **PDF目視正解** | 評価 |
|--------|------|-----|----------------|------|
| **P14** | 3 | 3 | **3** | ✅ V2.2もCSVも目視と一致（補正成功） |
| **P16** | 2 | 11 | **9** | ❌ V2.2も CSVも目視と不一致（三者不一致） |

### 重要な気づき

- **「CSV一致=正解」とは限らない**（P30が好例）
- **CSV値も誤りの可能性がある**ため、目視確認が必須のケースが存在
- **三者不一致（P16）**のような最難関ケースは、自動確定せず必ず人間確認に回す設計が正しい
- 「空欄」と「0」の区別は、後続比較ロジックで必須

## 精度説明の基本方針

### **重要ポイント**

1. **「OCR精度90%以上」と一括で言わない**
   - 項目別に精度が異なる
   - 条件によって精度が変わる
   - 「高精度」「中精度」「低精度」に分ける

2. **「完全自動化」ではなく「確認支援」**
   - AIが提案する
   - 人間が最終判定する
   - ログが残る

3. **危ないものは確認に回す**
   - 低信頼度 → 確認に回す
   - CSV不一致 → 確認に回す
   - 手書き正の字 → 確認支援する

4. **V2.2は「補助レイヤー」**
   - v3の誤読を補正する
   - 100%正確ではない
   - 人間判定が最終決定

---

## 項目別に精度を見る理由

### なぜ一括で「90%以上」と言わないのか

```
同じ「OCR読み取り」でも、以下で精度が大きく異なるから：

1. 項目によって異なる
   - AI合計欄 vs 手書き正の字
   - 数字 vs 文字
   - 自動記入 vs 手書き

2. 信頼度レベルで異なる
   - Confidence HIGH → 高精度
   - Confidence MEDIUM → 中精度
   - Confidence LOW → 低精度（要確認）

3. CSV照合結果で異なる
   - CSV値と一致 → 確実性高い
   - CSV値と不一致 → 確認が必要
   - 両者が不一致 → 危険信号

4. データ品質で異なる
   - FAX品質良好 → 高精度
   - FAX品質不良 → 低精度
   - 手書きが薄い → 低精度
```

**結論:** 単一の精度値では不十分。「どの条件で何%」かを説明する

## 自動確定候補にする条件

### 「自動確定候補」の定義

以下の **すべてを満たす** 場合のみ、自動確定候補にする：

1. **V2.2値がある**（AIが値を読めた）
2. **Confidence が HIGH または MEDIUM**（信頼度が高い）
3. **CSV値と一致している**（外部データと照合OK）
4. **v3からの乖離が小さい**（大きな誤読ではない）

### 自動確定候補の精度

```
条件を満たす「AI合計欄」の精度
└─ 約 85～90% 程度

理由：
- CSV 照合済み（一致）
- 信頼度フィルター済み
- v3 乖離チェック済み
- ただし100%ではない

補足：
- 手書き正の字は含まない（精度が低いため）
- 低信頼度は含まない（不確実なため）
- CSV不一致は含まない（検証が必要）
```

**大事なこと:** 「自動確定候補」は「確認済みとしてOK」という意味ではなく「このリストから優先度をつけて確認できますよ」という提案

---

## 要確認に回す条件

### 「要確認」に分類する理由

以下の **いずれかに該当する** 場合は、要確認に回す：

1. **Confidence が LOW**
   - AI読み取りの信頼度が低い
   - 手書きが薄い、FAX品質が悪い など

2. **CSV値と不一致**
   - V2.2値と CSV値が異なる
   - どちらが正しいか確認が必要

3. **v3 との乖離が大きい**
   - v3=34, V2.2=3（34倍の誤読）
   - AI補正が大きすぎる可能性

4. **V2.2値がない**（ブランク）
   - AIが読み取れなかった
   - 手書きが読めない

5. **手書き正の字**
   - 項目そのものが手書き
   - AIの精度が低い（50%程度）

### 要確認に回した場合の精度

```
「要確認」と判定されたアイテムについて

その中の正解率：
├─ Confidence LOW　　　　→ 50～60%
├─ CSV不一致　　　　　　 → 60～70%
├─ v3大乖離　　　　　　  → 70～80%
├─ ブランク　　　　　　  → 0% （読めていない）
└─ 手書き正の字　　　　 → 50～60%

結論：要確認に回したアイテムは「AIの判定を信じず、必ず人間で確認が必要」という意味
```

---

## 90%以上と言ってよい範囲

### ✅ 言ってよい場面

**「以下の条件を満たす『自動確定候補』の中では、AI合計欄の精度は85～90%程度です」**

- 限定的な範囲（自動確定候補のみ）
- 条件を明示している
- 「85～90%程度」で幅を持たせている

**例:**
```
「CSVと一致し、信頼度も高い項目では、
V2.2の精度は85～90%で、確認作業の優先順位付けに使えます」
```

---

## 90%以上と言わない範囲

### ❌ 言ってはいけない場面

**「OCR精度は90%以上です」** ❌ 絶対に言わない

理由：
- Confidence が low の場合は 50%程度
- 手書き正の字は 50～60%
- ブランクは 0%
- CSV 不一致は 60～70%

全体をざっくり平均すると、実際には **60～75%** 程度に落ちる

### 言ってはいけない理由

```
「90%以上」と言うと：
└─ ジオ様が「ほぼ自動化できる」と期待
   └─ デモ後に「精度が低い」と失望
   └─ 信頼関係が損なわれる
```

## AI合計欄V2.2の位置づけ

### V2.2とは

```
「補助レイヤー」
├─ v3（標準版OCR）の誤読を補正する
├─ AIが「この値の可能性が高い」と提案する
├─ ただし、100%正確ではない
└─ 最終判定は人間が行う
```

### V2.2の精度は「相対的」

```
v3 vs V2.2:

v3 だけ　　　　　 → 50% の精度
V2.2 で補正  　　→ 70～75% に向上
さらに人間で確認 → 95%+ に改善
```

**結論:** V2.2 は「v3 の精度向上」であり、「本採用ではなく確認支援」

## 手書き正の字の扱い

### 手書き正の字（マーク欄）の精度

```
AI読み取り精度：約 50～60%

理由：
- 手書きが多様（個人差）
- FAX品質の影響大
- 正の字の「統一基準」なし
- 読み取り誤りが多い
```

### 手書き正の字は「確認支援」に限定

✅ **できること:**
```
- 自動集計候補を事前に提示
- 要確認アイテムを優先順位付け
- 確認者の作業を効率化
```

❌ **できないこと:**
```
- 完全自動化
- 100%精度での自動判定
- 人間を完全に置き換える
```

```
「精度は、条件によって異なります。

・手書き正の字　　　　　　　　　　　 → 50～60%

自動確定候補と要確認に分けることで、
『精度が高いものから優先的に確認できる』という仕組みです。

本格導入時に、実データでの精度検証をさせていただきたいと考えています。」
```

```
「『危ないかもしれない』と AI が判定したものは、
 自動的に『要確認』に回します。

 これにより『誤確定防止』が実現します。」
```

## 言ってはいけない表現

❌ **絶対に言わない:**

```
・「OCR精度90%以上です」
  └─ 条件なしで一括で言うと誤解を招く

・「完全自動化できます」
  └─ 人間確認が必須なので不正確

・「人間確認は不要です」
  └─ 大間違い。人間確認が前提

・「AIが正解を確定します」
  └─ 人間が確定する。AI は提案するだけ

・「本採用確定です」
  └─ MVP の段階。本格導入は別

・「手書き正の字も完全に読めます」
  └─ 50～60%の精度。完全ではない

・「これで業務削減100%です」
  └─ 実データで検証が必須

・「誤確定は起きません」
  └─ 誤確定防止を『優先する』という意図。ゼロではない
```
