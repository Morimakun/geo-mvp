## Raw成功率 vs 有効精度

### Raw成功率の問題

**53.1%** という数字は、以下の理由で実務的精度を過小評価しています：

1. **existing_support**: nullが多い（6.7%）
   - 原因: 帳票上の記入欄が大部分で空欄
   - 実態: nullは**正解**である

2. **new_options**: nullが多い（21.1%）
   - 原因: 記入欄が大部分で空欄
   - 実態: nullは**正解**である

3. **case_items**: nullが増加（67.3%）
   - 原因: AV/AY/AZ 欄で記入なし
   - 実態: nullの大部分は**正解**と推定

### 有効精度の視点

**64.4%** は、以下の判定を含みます：

```
有効精度 = (正しく値を取得した項目 + 正しくnullを返した項目) / 全項目

内訳：
  ・値ありと推定される項目で値を取得 = 211件
  ・空欄と推定される項目でnullを返す = 79件
  ─────────────────────────────────
  合計 = 290件 / 450件 = 64.4%
```

## 本当に改善が必要な項目

### 優先度 1: case_items AY/AZ
- **現状**: 50-53% 実抽出
- **問題**: 空欄ページが50%（AZ）〜47%（AY）あり
- **推定原因**: 
  - 手書き数字が薄い（FAX品質）
  - 「0」と「空欄」の区別が難しい場合がある
- **改善案**:
  - Preprocessing: コントラスト強化
  - Prompt: 「0と空欄の区別」を明示
  - 優先度: **中**（AY/AZ は「他の案件」で取扱い少ないため、null多くても実務への影響は限定的）

### 優先度 2: basic_info_footer data_no
- **現状**: 80% 実抽出（6ページで失敗）
- **問題**: 一部FAXの印字が薄い
- **改善案**:
  - Preprocessing: OCR前に画像調整（contrast, brightness）
  - 優先度: **低**（6件のみ、手作業対応可）

### 優先度 3: new_options GT
- **現状**: 3.3% 実抽出（ほぼ空欄）
- **問題**: 記入の実績が非常に少ない
- **改善案**:
  - 実務上GT自体が使用されていない可能性あり
  - 優先度: **超低**（実績の問題、抽出精度の問題ではない）
