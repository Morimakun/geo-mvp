# Phase 6 SFAエクスポートExcel 列構造確認

**作成日：** 2026-07-07
**対象：** SFAエクスポートマスター 0625nn / 0626b / 0627b（CSVシート・283列）

---

## 1. 3日分のスキーマ差分

- **列数：283列で3ファイル完全一致**
- **列名・列順：3ファイル完全一致**（プログラムで全283列を突合済み）
- シート構成（6メタシート＋24店舗シート）も3ファイル同一
- 差分は行数のみ：0625＝24行、0626＝24行、0627＝26行（データ行）

→ **スキーマは3日分安定。日付ごとの列構造変化なし。**

## 2. 主要列の位置（CSVシート実測）

| 項目 | 列番号 | 備考 |
|------|--------|------|
| 法人・店舗(取扱コード) | **col1** | 旧検証の生CSVでは col281 だった。**このExcelでは1列目** |
| 紹介総数（AI合計欄対応候補） | **col36** | 旧検証の col35 から**+1ズレ** |
| お声がけ総数（CZ合計欄対応候補） | **col105** | 旧検証の col104 から**+1ズレ** |
| 日付 | **col283** | Excelシリアル値（46198=2026-06-25 等）。ファイル名の日付と一致 |

⚠️ **旧CSVの列番号をそのまま適用してはいけないことが実証された。** 生CSV（旧検証）とExcelのCSVシート（今回）で取扱コードの位置が281→1に移動し、数値列が+1ずれている。実装時は列名で解決し、列番号ハードコードを避ける。

## 3. 新SFA項目のCSV/Excel出力有無

**CSVシート283列の中に、以下の新帳票項目に対応する列は存在しない（キーワード全283列走査で確認）：**

- 営業形式（店舗／イベント区分）※「※イベント会場のみ」注記付きの既存列（col178-179等）はあるが区分列ではない
- 提出区分（初回／再送）
- スタッフID
- 日報データNo.
- タブレットNo.
- 店舗活動無しフラグ

→ **新SFA運用後も、CSV側スキーマは旧283列のまま**。同一店舗・同一日付の複数行（店頭／イベント）を区別する列は依然として存在しない。

## 4. データ行の状態

| 日付 | データ行 | 取扱コード空行 | 重複コード |
|------|---------|--------------|-----------|
| 6/25 | 24 | 6行（全項目None） | なし |
| 6/26 | 24 | 4行（全項目None） | なし |
| 6/27 | 26 | 0行 | **AU1KB830227（鶴見緑地）×2行、AU1KW740165（ニトリモール枚方）×2行** |

- 空行は「その日データがない店舗」のプレースホルダで、店舗別シートの日付欄 #N/A（未入力）店舗と数が一致する。
- 6/27の重複2店舗は、PDF側の**店舗＋イベント2枚提出**と対応（PAIRING_INITIAL_CHECK 参照）。

## 5. 店舗別転記シートの構造（照合上の重要資産）

各店舗シートは新帳票を1日1シートで再現：

| セル | 内容 |
|------|------|
| A1〜K1 | 日付（年/月/日/曜日）。未入力日は #N/A |
| P1 | 「1 店舗 2 イベント」ラベル（**記入値セルは未転記または別セル・要確認**） |
| A3〜I3 | AU1K＋店舗コード、L3 店舗名 |
| **V3** | **フル取扱コード（例 AU1KC490278）→ CSVシートcol1と直接結合可能** |
| V5 | 日付（シリアル値） |
| C7 | 提出区分ラベル（記入値セルは未転記・要確認） |
| **G14 / H14** | **通し番号5【案件】合計の紹介／声掛 ＝ AI/CZ合計欄相当の転記値** |
| V16〜Y20 | 【検算】欄（案件・内訳の新規/既存合計） |
| B55 | 通し番号25【内訳】合計 |

| P48 / P50 | 日報データNo.／タブレットNo.ラベル（番号値は未転記） |
