## 🔬 技術的原因分析

### Prompt の複雑化が Vision API を混乱させた

#### v3 Prompt（既存対応セクション）
```
簡潔さ：150 語程度
指示：BLANK vs ZERO を区別、テンプレート値を無視

結果：HH/HI/HJ で 6 個の値を抽出（低いが動作）
```

#### v4_rules Prompt（既存対応セクション）
```
複雑さ：250+ 語
指示：
  - BLANK vs ZERO を区別
  - テンプレート値（特に「40」）を強調警告
  - 3列テーブル構造を詳述
  - Column A/B/C の説明
  - 「40 を見たら IGNORE」という強い指示

結果：すべての値が null （0 個の値）
```

**仮説**: Vision API が「警告の多さ」を「判断停止の信号」と受け取り、安全側（null）に倒した。

## 🔍 v4_rules テストから得られた学習

### 教訓 1: Prompt レベルの過度な修正は危険

```
v3.1 失敗（match_rate 54.4% → 42.5%）
  → 「40 を絶対に読むな」という強い指示

v4_rules 失敗（existing_support 33% → 0%）
  → 「テンプレート値を避けよ」という複雑な指示

共通パターン：
  「1つのページの問題を Prompt で fix しようとしたら、全体が壊れた」
```

### 教訓 2: Vision API には「理解上限」がある

```
成功する Prompt：
  - シンプル（100-150 語）
  - 指示が明確（YES/NO で判定可能）
  - 例示が具体的（「0 か empty か」）

失敗する Prompt：
  - 複雑（200+ 語）
  - 条件付き指示が多い（「～の場合は～」）
  - テンプレート値の警告が多い（「これと これと これを避けよ」）
```

### 教訓 3: bounds（領域抽出）の重要性

```
問題の根本：
  - Page 28 HI=40 は「bounds が悪い」可能性が高い
  - テンプレート値「40」が視界に入る bounds 設定

Prompt での修正 ❌
  - 複雑化する
  - Vision API が混乱する
  - 全体に波及する副作用

bounds 調整 ✅
  - シンプル（座標の変更のみ）
  - Vision API に負荷をかけない
  - 問題を根本的に解決
```

  - 毎回同じ精度が出る

```
既存対応+新規オプション：85.7%（v3 の結果）
  HH/HI/HJ の精度：66% 平均
  GS/GT/GU の精度：60% 平均（P8 除外時）

MVP スコープでは「これで十分」
```

### 3. 将来の改善が可能

```
Prompt は修正しない（複雑化の危険）
代わりに bounds 調整で改善（v3.2）

この分離により：
  - 安定性を保ちながら
  - 段階的に精度向上
```
