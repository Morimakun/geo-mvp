### パターン A：店頭/イベント が CSV で別行になる

**ジオ様の回答:**
```
「店頭」「イベント」は Salesforce で別行で入力されます。
営業形式を区分する列があります。
```

**実装方針:**

1. **照合キー拡張**
   ```
   従来: 店舗コード + 営業日
   修正: 店舗コード + 営業日 + 営業形式（新）
   ```

2. **app.py での変更**
   - CSV読込時に営業形式列を取得
   - 照合フロー：`(店舗コード, 営業日, 営業形式)` で一意に行を特定
   - UI表示：「営業形式」区分タブを追加

3. **CSV列番号の確認**
   - 営業形式が「どの列」に入っているか確認
   - 対応表.pdf に営業形式の列記号を追記

4. **ロジック変更**
   ```python
   # 従来
   csv_key = (store_code, business_date)
   
   # 修正
   csv_key = (store_code, business_date, business_format)
   ```

5. **テスト対象**
   - イオンモール神戸北（店頭/イベント分離確認）
   - 鶴見緑地（5/17で複数営業形式）

### パターン B：店頭/イベント が合算される

**ジオ様の回答:**
```
「店頭」「イベント」は Salesforce で 1 行に合算されます。
営業形式の区分列はありません。
```

**実装方針:**

1. **照合キーは変更しない**
   ```
   店舗コード + 営業日（そのまま）
   ```

2. **app.py での変更**
   - PDF読込時に複数帳票を検出
   - 同一店舗×同一営業日で複数帳票 → AI/CZ値を合算
   - UI表示：「複数帳票があります」という注記

3. **合算ロジック**
   ```python
   # PDF側（複数帳票がある場合）
   if multiple_forms:
       pdf_ai_total = sum(form.ai for form in forms)
       pdf_cz_total = sum(form.cz for form in forms)
   
   # CSV側（既に合算済み）
   csv_ai = csv_row[col35]
   csv_cz = csv_row[col104]
   
   # 比較
   match = (pdf_ai_total == csv_ai) and (pdf_cz_total == csv_cz)
   ```

4. **テスト対象**
   - イオンモール神戸北（P14+P9 を合算）
   - 鶴見緑地（複数行を合算）

### パターン C：Excel マスター正式版に決定

**ジオ様の回答:**
```
「店舗名　スタッフ名.xlsx を正式マスターとします。
 更新時は新しい Excel を差し替える運用で構いません。」
```

**実装方針:**

1. **マスター管理**
   ```
   data/master/
   ├── store_master_latest.xlsx（本番用・定期更新）
   └── store_master_history/
       ├── store_master_20260611.xlsx
       ├── store_master_20260620.xlsx
       └── ...
   ```

2. **app.py での読込**
   ```python
   # 起動時に最新マスターを読込
   store_master = pd.read_excel("data/master/store_master_latest.xlsx")
   
   # キャッシュ保持（セッション内で使用）
   st.session_state['store_master'] = store_master
   ```

3. **更新フロー**
   - ジオ様から新しい Excel を受け取る
   - `data/master/` に date-stamp をつけて保存
   - `store_master_latest.xlsx` を上書き
   - git で履歴管理

4. **テスト対象**
   - 24 店舗すべてがマスターに含まれているか確認
   - 新しい店舗追加時の追加手順を確認
