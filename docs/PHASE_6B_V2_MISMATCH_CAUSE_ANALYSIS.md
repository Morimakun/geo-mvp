## 詳細分析

### ①正の字過大評価（2件）

```
Page 8: GS (eo光電話) — PDF=5 vs CSV=1
Page 8: GU (CS) — PDF=5 vs CSV=1
```

**原因**: Vision API が「正」の字の部分的な線描を「5」（完成）と判定

**対策**: 
- Prompt で「複数本の確実な線」のみ正の字とするよう指示
- 正の字カウントの「完成判定」をより厳密化

**改善による効果**: これら2件を null or 1 に修正可能

---

### ②正の字過小評価（2件）

```
Page 13: GU (CS) — PDF=2 vs CSV=1
Page 21: GU (CS) — PDF=1 vs CSV=0
```

**原因**: Vision API が線の一部を見落とし、正の字を1〜2画として認識

**対策**: 
- Prompt で「T字形」「7字形」を2として認識するよう追加
- 線の途中で途切れている場合の扱いを明確化

**改善による効果**: 1件改善（Page 21 は逆ズレなため要確認）

---

### ③手書き数字誤読（7件）

```
Page 0: AU — PDF=5 vs CSV=4  (+1 誤読)
Page 5: AU — PDF=1 vs CSV=2  (-1 誤読)
Page 7: AU — PDF=0 vs CSV=1  (-1 誤読)
Page 12: AV — PDF=1 vs CSV=0  (+1 誤読)
Page 16: AU — PDF=0 vs CSV=1  (-1 誤読)
Page 28: AU — PDF=1 vs CSV=3  (-2 誤読)
Page 28: AV — PDF=1 vs CSV=0  (+1 誤読)
```

**原因**: 手書き数字の OCR が0-9を1～2ずれて認識

**対策**:
- PDF のズーム率を上げて、手書き数字領域の解像度向上
- Prompt で「0と空欄の区別」「1と7の区別」を明示

**改善による効果**: 5～7件改善可能

**対策**:

2. **長期**: 内訳フィールドを完全抽出して、PDF合計値を検証

**対策**:

2. **目視確認**: Page 6（AY, HI）など、実際の帳票を確認

**改善による効果**: 5～9件改善可能（ケース B, C）

## 次に直すべき Prompt / Bounds

### 優先度 1（即座 / Prompt 1-2行の追加）

#### A. 正の字カウント精度

**現在の Prompt**:
```
「正」の字を5としてカウントしてください
```

**改善案**:
```
「正」の字を正確にカウント：
- 横棒1本: 1
- 横棒2本 (T字型): 2
- 完成した「正」(5本の線が交差): 5
部分的な線や途中で途切れている線は数えないでください
```

**効果**: ①②を解決（4件）

#### B. 0 と空欄の区別

**現在の Prompt**:
```
数字が記入されていない場合は null としてください
```

**改善案**:
```
区別してください：
- 何も記入されていない: null
- 「0」が明確に書かれている: 0
薄い手書きや不確実な場合は uncertain としてください
```

**効果**: ⑥を部分改善（3～5件）

#### C. 手書き数字の確実性

**現在の Prompt**:
```
手書き数字を読み取ってください
```

**改善案**:
```
手書き数字の読み取り：
- 確実に読める場合: 数値
- 0 と 6, 1 と 7 など区別が難しい場合: uncertain
- 全く読めない場合: null
```

**効果**: ③を部分改善（2～3件）

### 優先度 2（Bounds 調整 / 領域最適化）

#### D. 手書き領域のズーム

**現在**:
- bounds の top%, left%, right% は全体比率（0-100%）
- 手書き数字エリアが小さく、解像度が低い

**改善案**:
```python
# 手書き数字エリア（AU, AV, AY, AZ）のみズーム
if item_code in ['AU', 'AV', 'AY', 'AZ']:
    bounds = (top%, bottom%, left%-5%, right%+5%)  # 左右に5%余裕
    zoom_factor = 2.0  # 2倍ズーム
```

**効果**: ③を追加改善（2～3件）

### 優先度 3（長期 / Phase 6B 拡張）

#### E. AI合計値の直接抽出を廃止

**現在**:
- PDF の AI 行を直接数字として読む
- しかし内訳が未抽出のため合計が合わない

**改善案**:
1. 内訳フィールド（個別製品のケース数）を20フィールド追加抽出
2. AI 行は「検証用参考値」とし、合計値の検証に使う
3. CSV側の合計と照合

**効果**: ④を改善（10～12件）
