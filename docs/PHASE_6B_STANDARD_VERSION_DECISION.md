## ❌ v3.1 不採用決定

**バージョン**: `scripts/evaluate_phase6b_30pages_v3_1.py`

### 不採用理由

#### 1. 予想外の副作用

| 指標 | v3 | v3.1 | 変化 |
|------|-----|--------|------|
| match_rate | 54.4% | **42.5%** | **-11.9pt** ❌ |
| existing_support 抽出 | 27/90 | **4/90** | **-23件** ❌ |

#### 2. 改善効果の不足

```
目的: Page 28 HI=40 を修正
結果: HI=40 は修正されたが、全体が壊れた

修正前（v3）:   Page 28 HI=40 のみ問題
修正後（v3.1）: existing_support 全体が壊れた
```

#### 3. Prompt レベルの過度な修正

```
v3.1 Prompt 追加:
  「40 を見たら絶対に null」
  「テンプレート値は NEVER return」

結果:
  全ページで existing_support が null 化
  意図: Page 28 の 1 件を fix
  実害: 全 30 ページのうち 23 件が消失
```

**教訓**: Prompt での強い警告は、Vision API の「判断停止」を招く。

## ❌ v4_rules 不採用決定

**バージョン**: `scripts/evaluate_phase6b_30pages_v4_rules.py`

### 不採用理由

#### 1. 既存対応と新規オプションが完全に崩壊

**6 ページテスト結果**:

| 領域 | v3 成功率 | v4 成功率 | 変化 |
|------|---------|---------|------|
| existing_support | 33.3% | **0%** ❌ | -33.3pt |
| new_options | 11.1% | **0%** ❌ | -11.1pt |

#### 2. 複雑すぎる Prompt が原因

```
v4_rules Prompt の問題:
  - existing_support: 250+ 語（v3 の 2 倍以上）
  - テンプレート値警告が 15+ 個
  - Column A/B/C 構造を詳述
  - 例示が複数

Vision API の反応:
  「複雑すぎてわからない」
  → 安全側（null）で返す
  → 結果: 全て null
```

#### 3. v3.1 と同じ失敗パターン

```
v3.1 失敗: Prompt 強調 → existing_support 崩壊
v4_rules 失敗: Prompt 複雑化 → existing_support + new_options 崩壊

共通原因: Prompt レベルの修正の限界
```

## 🔬 技術的分析：なぜ Prompt 修正は失敗するのか

### Vision API の理解能力の限界

```
成功する Prompt:
  - 簡潔（100-150 語）
  - 指示が YES/NO で判定可能
  - 例示が 2-3 個

失敗する Prompt:
  - 複雑（200+ 語）
  - 条件付き指示が多い（「～の場合は～」が 5+ 個）
  - テンプレート値の警告が多い（「これと これと これを避けよ」）
  - 例外が多い（「ただし～は例外」が複数）
```

### なぜ「強い警告」は逆効果なのか

```
Prompt に「40 を NEVER return」と書くと:
  1. Vision API は「40 という値について、判定が難しい」と理解
  2. 代わりに「全て null」で安全側に倒す
  3. 結果: 想定外の全体崩壊

理由:
  - Vision API は「判断基準の優先度」を学習できない
  - 「警告が多い = 判断が難しい」と解釈
```

## ✅ 今後の改善方針：Prompt 複雑化を避ける

### 禁止事項

```
❌ Prompt を複雑化しない
❌ テンプレート値の警告を増やさない
❌ 条件付き指示を増やさない
❌ 例外を追加しない
```

### 推奨事項

```
✅ v3 の Prompt は変更しない（安定性優先）
✅ 改善は「領域分割」（crop 調整）で行う
✅ 改善は「後処理」で行う
✅ 改善は「対象項目限定」（case_items のみなど）で行う
```
