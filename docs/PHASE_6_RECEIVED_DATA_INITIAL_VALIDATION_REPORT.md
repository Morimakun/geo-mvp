## 3. Excel構造

## 4. 3日分のスキーマ安定性
**283列の列名・列順は3ファイル完全一致。** 差は行数のみ。→ スキーマは安定。

## 5. 新SFA項目のCSV出力有無
**出力されていない。** 営業形式・提出区分・スタッフID・日報データNo.・タブレットNo.・店舗活動無しのいずれもCSVシート283列に対応列なし。同一店舗・同一日付の複数行を区別する列も従来どおり存在しない。

## 6. PDFとExcelの対応候補
- 店舗コード（帳票プレプリント）⇔ 転記シートV3のフルコード ⇔ CSVシートcol1 が直結
- 転記シートの通し番号5合計（紹介/声掛）⇔ CSV紹介総数(col36)/お声がけ総数(col105)は、**6/25=18/18、6/26=20/20、6/27=21/24で一致**
- 6/27不一致3件（明石大久保0vs2・くずはモール7vs13・大日4vs6）は本レポート時点では原因未特定 → 先方確認候補（**追記：明石大久保は後日のVision試験でPDF原本=CSVの可能性が高いと判明。詳細は VISION_SAMPLE_TEST_RESULT・MISMATCH_RECHECK_RESULT 参照**）
- **鶴見緑地・ニトリ枚方は6/27に店舗＋イベント2枚⇔CSV2行が完全対応**（照合キー「店舗×日×営業形式」の実例を確認）
- 一方、堺北花田・神戸北もイベント帳票があるのにCSVは1行のみ → 計上ルール要確認
- **枚方船橋の帳票は当初PDF内で確認できないとしていたが、撮影形式ページ（P2/P31/P65）として存在することが後日判明**（詳細は PDF_PAGE_QUALITY_REVIEW 参照）

## 9. AI/CZ合計欄の読み取り見込み
- 新帳票の合計欄は旧と同型構造（通し番号5の紹介/声掛）で、記入も明瞭なページが大半 → プロンプト調整で読み取れる**見込み**（未検証）

## 10. 旧帳票ロジックへの影響見込み
