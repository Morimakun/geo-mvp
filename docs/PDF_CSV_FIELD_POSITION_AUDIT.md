## 2. 【最重要】0-index / 1-index 検証

### 突合本体のCSV値取得ロジック

`reconciliation_phase1.py` `_compare_fields()` 内、L859-879：

```python
# Step 4: CSV値を取得（1-indexed → 0-indexed）
csv_col_idx = int(csv_column_number) - 1      # 35 → 34
if csv_col_idx >= len(csv_row) or csv_col_idx < 0:
    ... skipped_csv_null ...
csv_value = csv_row.iloc[csv_col_idx]          # iloc[34]
```

- `csv_column_number` は **1-indexed**（スプレッドシート列字準拠）。
- `iloc` は **0-indexed**。
- `- 1` で正しく変換している。AI(35) → `iloc[34]` → pandas先頭からの35番目の列 → スプレッドシート列AI。**一致。**

旧スコアリング `_calculate_score()` L404 も同じ `- 1` 変換で一貫：
```python
csv_val = csv_row.iloc[int(csv_col) - 1] if csv_col > 0 else None
```

#### 間接検証：突合結果の一貫性

もし index が1つズレていれば、**全項目が隣の列を読む**ため、一致は偶然レベル（ほぼ0）に崩壊するはず。実際の突合結果 `phase6b_v3_reconciliation_page_summary.csv`：

- 店舗コード特定：**29/30ページ成功**（P17のみ店舗名読取不可）
- フィールド一致：多くのページで `match_count` 3〜7
- **P24 高砂明姫：status=match、2項目一致・0不一致（完全一致）**

→ index がズレていれば P24 の完全一致や match_count=7 は起こり得ない。**0/1-index の扱いは正しいと実証される。**

### 店舗コード列の検出も整合

`_detect_store_code_column_index()` は列名（'取扱'+'コード'）優先、なければ index 280（列JU=281）にフォールバック。29/30で店舗コードによる行特定が成功していることから、**CSVの実列位置とマスター列番号が1:1で整列している**ことが確認できる。

## 3. PDF側の抽出位置監査（右ブロック混入チェック）

PDF抽出は `scripts/evaluate_phase6b_30pages_v3.py` の `REGIONS` 定義で、**列番号ではなく項目コードでクロップ領域内を読む**方式。よって 0/1-index 問題はPDF側には存在しない。検証点は「AIを左ブロックの合計セルから読んでいるか」のみ。

### case_items 領域（AU/AV/AY/AZ/AI の出所）

```python
"case_items": {
    "bounds": (12, 24, 0, 45),   # 左帯（x 12-24%）× 上部（y 0-45%）
    "items": ["AU", "AV", "AY", "AZ", "AI"],
    "prompt": "...Total row (合計) → AI ..."
}
```

- クロップは **x=12-24% の狭い左帯**。右ブロック（額対応 0,40,15…）は含まれない。
- プロンプトは「紹介(referral)列の各行」と「合計行 → AI」を読む指示。
- 比較として `existing_support`（x=12-22, y=65-100）は右側の「中央のテンプレ数字 40/15 を無視せよ」と明示。**右ブロック値は別領域で除外管理されている。**

→ **AI は左ブロックの合計セルから読まれており、右ブロック（0,40,15…）の混入はない。** ユーザー確定定義と整合。

### AI は「計算」ではなく「合計セルの直接読取」

プロンプトは AI を AU+AV+AY+AZ から計算させず、**合計行の手書き値をそのまま読む**。
→ よって「PDF AI ≠ PDF内訳合計」は **マッピング誤りではなく**、(a) 内訳セルが空欄/uncertainで抽出されない、または (b) 合計セルの手書き値そのものの読取、に起因する。

## 4. 13件差分の原因（マッピング監査の結論として）

監査の結果、**13件はいずれもマッピング／index のズレが原因ではない。** 残る原因は：

| 原因 | 説明 | 該当例 |
|------|------|--------|
| **PDF合計セルの読取値** | 大きな手書き値の読取信頼性（要原紙確認） | P14=34, P11=20, P24=7 |
| **PDF内訳の抽出不完全** | AU/AV/AY/AZ が null/uncertain で合計を検証不可 | P12, P28（内訳全null） |
| **CSV側の集計タイミング・範囲** | Salesforce列35の更新時点・集計期間 | P12/P28（PDF=0だがCSV=2の逆パターン） |
