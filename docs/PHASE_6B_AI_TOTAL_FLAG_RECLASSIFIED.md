## 2. 新しい原因分類（A～G）

### A. PDF読取位置の問題
**条件：** AI値が異常に大きく、内訳ともCSVとも大きくズレる。
**原因：** Vision API のクロップ領域が誤り、違う欄の数字を AI として読み込む。
**対処：** クロップ座標の見直し。

**該当件数：0**

---

### B. PDF手書き値の読取ミス
**条件：** AI欄の数字として認識されているが、OCR誤認識の可能性。例：「2」→「34」、「1」→「7」など。
**判断基準：**
- AI値が異常に大きく、内訳と大きくズレ（P14=34で内訳=2など）
- または AI値が内訳より大きい（P24=7で内訳=1など）
- または AI値と内訳が混在する不整合

**該当件数：4**
- P14（ページ13）イオンモール神戸北：PDF AI=34（内訳=2）→ 「34」が「2」「3」「4」の誤読か確認必須
- P24（ページ23）六甲道：PDF AI=7（内訳=1）→ 「7」が「1」の誤読か確認必須
- P30（ページ29）JR神戸北：PDF AI=2（内訳=1）→ 「2」が「1」の誤読か確認
- P16（ページ15）熊取：PDF AI=9（内訳=2+uncertain）→ 「9」の妥当性確認

---

### C. 内訳項目の抽出不足
**条件：** AU/AV/AY/AZ の一部または全部が null/empty で、内訳合計が検証できない。
**判断基準：**
- null_count >= 2（2つ以上の内訳が空）
- AI値があるが内訳が空の場合、AI値の妥当性検証不可

**該当件数：4**
- P11（ページ10）深江橋：内訳全null。AI=20だが検証不可
- P12（ページ11）広畑：内訳全null（4 null）。AI=0だがCSV=2。blank vs 0区別失敗の可能性
- P20（ページ19）魚住：AU+AV=4だがAY/AZ未抽出。AI=6の妥当性不完全検証
- P28（ページ27）宝殿：内訳全null（4 null）。AI=0だがCSV=2。P12と同じパターン

---

### D. PDFとCSVの実差分
**条件：** PDF AI値と内訳が妥当に見えるが、CSV値とズレる。
**判断基準：**
- PDF内訳 vs PDF AI が整合する、または小さい差分
- PDF AI vs CSV AI が大きくズレる
- 理由：Salesforce側の更新タイミング・範囲の違い、または業務実績の差

**該当件数：4**
- P2（ページ1）イオンモール大日：PDF=0（内訳=0）vs CSV=2。後入力・更新タイミング差
- P10（ページ9）イオンモール大日：同一店舗。PDF=0（内訳=0）vs CSV=2。タイミング差
- P29（ページ28）松井山手：AU PDF=2 vs CSV=3。1ズレだが内訳不完全なので実差分と判定
- P9（ページ8）イオンモール神戸北：AU PDF=2 vs CSV=1。内訳不完全だが実差分か

---

### E. 比較ロジックの問題
**条件：** PDF/CSV両方正しく読取・抽出されているが、比較時の処理誤り。
**判断基準：** reconciliation_phase1.py のロジック検証で判明するもの。

**該当件数：0**（今回の監査では関連事例なし）

---

### F. 手書きルール例外
**条件：** 正の字が途中形、または数字欄に特殊記入（確度「uncertain」）。
**判断基準：** AZ/AY が「uncertain」フラグの場合。

**該当件数：1**
- P16（ページ15）熊取：AZ=uncertain。正の字途中形の可能性。AI=9が正の字基づくか確認

---

### G. 要目視確認
**条件：** 上記A～Fが混在、または複合的で判断不可。
**判断基準：** 原紙目視・Salesforce確認・ユーザー確認が必須。

**該当件数：1**
- P15（ページ14）イオンモール大日：AU/AV未抽出、AY+AZ=2だがAI=4。内訳不完全で複合的判定不可

## 5. AI FLAG を製品説明上どう扱うか

### 現在の立場

**AI抽出は成功している。FLAG 13件は「失敗」ではなく「差分候補の検出」。**

| 状態 | 説明 | Tier |
|------|------|------|
| **AI 一致** | PDF = CSV（7件） | **Tier A** |
| **AI 不一致** | PDF ≠ CSV（13件） | **Tier B/C** |
| **AI null** | PDF/CSV読取不可（10件） | **Tier C** |

→ **AI 一致なら自動確定候補。AI 不一致は「差分要確認」として扱い、以下で分類：**

- **B（読取ミス）** → Vision API精度改善で対応
- **C（内訳不足）** → blank vs 0区別、正の字ルール改善で対応
- **D（実差分）** → 業務実績の差。確認サポートで対応
- **F/G（例外・複合）** → 要目視確認。後処理でreview化

### 製品ストーリー

**「AI合計欄は抽出を100%成功しています。ただし、抽出値がSalesforceと異なる場合は以下のいずれかです：**
1. **PDF内訳の読取精度** — AU/AV/AY/AZ の blank vs 0 を改善
2. **PDF合計値の読取正確性** — 手書き数字の誤読可能性を確認
3. **業務実績の差** — PDF記入日時とSalesforce更新のタイミング差
4. **確認支援が必要** — 上記で判定できない複合ケース

**→ Tier A/B/C で透明に分類し、確度を明示。**

## 7. 次の技術改善候補

### 短期（Phase 6B完成向け）

#### 7.1 Vision API プロンプト改善
**課題：** B. 読取ミス（34→2？、7→1？）の疑い

**対処：**
- 合計（AI）欄を単語確認。「合計」「合計（数字で記入）」の直下 1行という場所指定
- 数字の OCR 精度。3桁と1桁の区別を明示（例：「1文字か3文字か」）
- 正の字カウント（5段階）を「正の字 / 数字」で区別

**実装候補：**
```
（Vision プロンプト）
合計（AI）欄：「合計（数字で記入）」行の紹介列セルから、
1）正の字カウントの個数（0～5個）、または
2）算用数字（1,2,3,4,7など）を読み取ってください。
3位数の場合は「34」「20」と明示してください。
不確実な場合は「uncertain」とマークしてください。
```

#### 7.2 blank vs 0 の区別改善
**課題：** C. 内訳不足（P12/P28で内訳全null）

**対処：**
- case_items クロップ領域の確認（左帯 x12-24% に限定）
- 「0」と「空欄」を別コード化（0 vs blank）
- Vision プロンプトで「セルに文字が見えるか」を確認

**実装候補：**
```
（Vision プロンプト）
AU/AV/AY/AZ 項目欄：
- セルに「0」が見える場合：0
- セルが白/空白：blank（null ではなく明示的に区別）
- セルに他の数字：その数字
```

#### 7.3 正の字カウント途中形の Tier C 化
**課題：** F. ルール例外（P16 AZ=uncertain）

**対処：**
- uncertain フラグの項目は自動確定しない
- Tier C（確認支援）に分類
- 後処理で uncertain → review に変換
