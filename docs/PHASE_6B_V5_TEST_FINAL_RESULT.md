## 🔍 詳細分析

### v5 が成功した項目：AZ

```
AZ（その他案件既存）の抽出結果:

v3: P1=null, P6=null, P8=null, P10=null, P15=1, P28=null → 1/7
v5: P1=5, P6=30, P8=0, P10=2, P15=0, P28=null → 5/7

改善: 14% → 71% (大幅改善)

ただし、P6=30 は異常値の可能性
  - CSV では通常 0-5 の範囲
  - 30 は明らかに大きすぎる
  → crop 境界か誤読の可能性
```

### v5 が失敗した項目：AI

```
AI（合計数字欄）の抽出結果:

v3: P1=5, P6=3, P8=1, P9=2, P10=0, P15=4, P28=0 → 7/7 (100%)
v5: すべて null → 0/7 (0%)

理由: AI 行の crop bounds が不適切の可能性
  - AI 行は case_items の最後の小さな行
  - 現在の bounds: (24, 24.5, 0, 45) — 高さ 0.5% は短すぎる可能性
  - Vision API が画像として解釈できない可能性

影響: AI は v3 で 100% 成功しているため、v5 での回帰は致命的
```

### v5 が部分失敗した項目：AU/AV/AY

```
AU: 57% → 29% (悪化)
AV: 43% → 0% (完全失敗)
AY: 29% → 14% (悪化)

原因推定:
  - crop 行分割が理論的には正しいが、実装に問題
  - 行高さの設定が不正確の可能性（他行との干渉）
  - Prompt は改善されたが、crop 境界のズレが上回った
```

## 💡 重要な知見

### V5 分割アプローチの理論は正しい

```
根拠:
  1. AZ で改善確認（分割 crop が機能している証拠）
  2. AU でも値の抽出が確認できた（完全失敗ではない）
  3. 問題は実装品質（bounds 微調整が必要）
  4. v3.1/v4_rules と異なり、回帰レベルが軽微
```

### しかし現在の実装は本採用不可

```
理由:
  1. AI の 100% 失敗（数字欄の回帰は致命的）
  2. AV の 0% 成功（実用的でない）
  3. 全体では v3 に劣る（49% → 23%）
  4. 異常値（P6 AZ=30）の発生
```
