## 💬 丸山様向け説明文

### 提案内容

PDF全30ページの読取テストを完了しました。以下がテスト結果です。

**高精度で読み取れている項目：**
- 日付、日報DataNo、タブレットNo → 全ページで100%正確

**一定程度読み取れるが、確認が必要な項目：**
- 担当者名 → 70%は正確に読めていますが、カタカナ、数字混入、手書きの崩れにより、30%は誤読や部分読取が発生しています。そのため、システムが読み取った担当者名は自動確定ではなく、確認画面で人が修正できる前提にするのが安全です。

**今後の対応予定の項目：**
- 正の字（tally mark）、手書き数字、集計欄 → 手書き認識の精度改善が必要なため、Phase 6B以降で対応予定

**初期版での位置づけ：**
初期版では、読み取り精度が高い「日付・DataNo・TabNo」を中心に、PDF帳票とSalesforce CSVの照合を支援します。担当者名については、機械読取値を参考情報として提示し、人が最終確認・修正する方式とします。

## 🔍 技術的な知見

### Vision API の読取傾向

**読め る もの：**
- ✅ 明瞭な漢字（原田、山本など）
- ✅ 明瞭なカタカナ（ニノミヤなど）
- ✅ 数字（DataNo、TabNo）
- ✅ アルファベット

**読みにくい もの：**
- ⚠️ 複雑な漢字（片木優一→読める、尾山椛侍人→読める、片大橋→一部失敗）
- ⚠️ カタカナ + 数字の混在（「909」は「クロダ」を誤検出）
- ⚠️ 手書きの崩れ、スペース挿入
- ❌ 正の字（tally mark）
- ❌ 手書き数字（精度±20%）
- ❌ 黒塗り部分

### 推奨される改善策

1. **短期**（初期版）
   - 日付・DataNo・TabNo → 今回サンプルでは高精度確認、別帳票での再現性確認後に活用
   - 担当者名 → OCR結果 + マスタ突き合わせで候補提示、人が最終確定
   - 正の字・集計欄 → 現時点では要目視確認、確認負担軽減の優先度は低

2. **中期**（Phase 6B）
   - テンプレートマッチング導入（FAX帳票の座標固定を活用）
   - Vision API のプロンプト調整（カタカナ・数字に特化した指示）

3. **長期**（Phase 6C）
   - 手書き数字認識の精度向上
   - OCR前処理の改善（解像度UP、ノイズ除去）
   - 複数モデルのアンサンブル
