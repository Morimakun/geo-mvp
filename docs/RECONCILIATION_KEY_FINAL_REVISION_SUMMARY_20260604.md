### 2. 日報Noは除外（確定）

```

✓ 参考情報（監査用トレーサビリティ）
```

**理由**: あてにならない（バージョン管理なし、重複、欠番など）

### 3. タブレットNoはCSV側に列がない（確定）

```
CSV側に列なし
↓
直接照合キーに使えない
↓
PDF側の店舗推定補助として使用のみ
```

**フロー**:
```
PDF上のタブレットNo
  ↓
店舗備え付け端末 → 店舗推定の参考
  ↓
でも最終判定は CSV側の店舗コード + 集計値
```

### 4. 本命キーは「日付 + 店舗コード + 集計値一致度」（確定）

```
日付 + 店舗コード（CSV列281）
  ↓
CSV候補行を絞る
  ↓
PDF抽出値 vs CSV値 の一致度で判定
  ↓
一致 / 不一致 / 要確認
```

## 重要な実装ポイント

### 1. 複数候補時の判定ロジック

```python
# 同一店舗・同一日付で複数CSV行がある場合
if len(candidates) > 1:
    # 一致項目数が多い順に並べる
    for csv_record in sorted_by_match_count(candidates):
        match_count = count_matching_items(csv_record, pdf_data)
        
        if match_count == all_items:
            # 完全一致
            return csv_record, "一致"
        elif match_count > threshold:
            # 主要項目一致
            return csv_record, "一致"
    
    # 複数候補が同等
    return None, "要確認"
```

### 2. ステータス分類の厳密性

```
一致: 主要マッピング項目が一致（差分なし or 許容値内）
不一致: 主要マッピング項目に差分あり（許容値超過）
要確認: 店舗候補が複数 or 見つからない or 読取失敗
```

### 3. タブレットNoの使い方

```
PDF上: 店舗を推定する際の参考情報
CSV側: 対応列がない → 直接照合キーに使えない
→ PDF側で店舗推定精度を上げるための補助情報のみ
```
