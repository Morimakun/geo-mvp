## 🔍 「209」問題の本質

### ユーザー目視確認で確定

| 情報 | 詳細 |
|------|------|
| **見かけ** | 「209」（数字） |
| **実体** | カタカナ「クロダ」のOCR誤読 |
| **マスタ状態** | 未登録（過去資料で「クロダ」「黒田」「くろだ」とも未登録確認） |
| **発生ページ** | P2, P10（少なくとも2ページ確認） |

### 問題の本質

```
仮説 A（修正前）：「209」は別欄の数字を拾った
  → ❌ 誤り

正体（確定）：「クロダ」のOCR誤読
  → Vision API が人名を誤読
  → マスタに登録されていないスタッフ
  → 複数ページで同じスタッフが誤読されている
```

### 根本原因

1. **Vision API の人名OCR精度の限界**
   - カタカナ名の誤読率が高い
   - 「クロダ」→「209」という変換理由は不明

2. **スタッフマスタの登録漏れ**
   - 「クロダ」がマスタに存在しない
   - 過去メモで「未登録候補」として指摘済み

3. **スタッフ名表記ゆれの可能性**
   - 「クロダ」「黒田」「くろだ」などの別表記がマスタにあるか確認が必要

### 対策

```
短期：
  ✓ 「クロダ」の正式表記・staff_no を片山様に確認
  ✓ マスタに登録漏れがあれば追加

中期：
  - Vision API の人名OCRプロンプト改善
  - マスタにエイリアス（alias）列を追加検討

長期：
  - 店舗コードから在籍スタッフ候補を絞る（補助用）
  - OCR候補をレビュー表示する UI
```

**Crop**: `p010_basic_info_header_209.png` で確認（実際は「クロダ」と手書きされている）

## ⚠️ bounds / prompt 改善の必要性

### 現在の設定

```python
# basic_info_header: (0, 14, 0, 100) → (top%, bottom%, left%, right%)
bounds = (0, 14, 0, 100)
zoom = 2

# Prompt
"Reporter's name (handwritten Japanese name)"
```

### 問題点

1. **「209」が拾われている** → bounds が隣フィールドに重なっている可能性
2. **87.1% が no_match** → Prompt が不十分か、bounds が間違っているか

### 改善案

#### 短期：bounds の確認

```
action: crop 画像を目視確認
  - P1: スタッフ名位置確認
  - P10: 「209」がどこから来ているか確認
  - P11: 唯一成功したページとの比較

確認項目：
  - 左側：「209」や別の数字が見える位置にあるか
  - 右側：スタッフ名の右端に余裕があるか
  - 上下：不要なテキスト（日報 No など）が含まれているか
```

#### 中期：Prompt の詳細化

```
案 1: スタッフ名フォーマットを明記

現在：
  "Reporter's name (handwritten Japanese name)"

改善：
  "Reporter's name (handwritten Japanese person name).
   - Only extract the personal name (full name or family name)
   - Do NOT extract numbers, IDs, or printed template values
   - Common names: (list 5-10 examples from staff_master)"

効果：
  - Vision API に「何が名前か」を明確化
  - 「209」などの数字の除外
```

案 2: 負のプロンプト

```
"Do NOT extract: numbers, printed values, dates, form IDs, tablet numbers"
```

#### 長期：bounds 微調整

```
action: 小規模テストで bounds を段階的に変更
  - left: 0 → 2（左側の数字フィールド除外）
  - right: 100 → 95（右側の余白除外）
  - height: 0-14% → 3-13%（上下の枠線除外）

小規模テスト：P1, P8, P9, P10 の 4 ページで検証
```
