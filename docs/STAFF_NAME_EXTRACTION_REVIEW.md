## 🔍 「209」問題の詳細分析

### 発生ページ

- P2 (page_index 1): 「209"」
- P10 (page_index 9): 「209」

### 正体候補

| 候補 | 根拠 | 可能性 |
|------|------|--------|
| **スタッフ ID** | staff_no は 1001～1028 | 低い |
| **店舗番号** | PDF 帳票に店舗 ID が印字 | 中程度 |
| **日報 No の一部** | data_no の先頭が「00」なら、後続が「209」の可能性 | 中程度 |
| **タブレット No の一部** | tablet_no に「209」が含まれる可能性 | 中程度 |
| **別フィールド** | basic_info_header bounds が隣に重なっている | 高い ← **最有力** |

### 対策

```
最優先：crop 画像で「209」がどこから読まれているか目視確認
  → bounds が左右・上下にズレていないか確認
  → スタッフ名欄か、隣の欄（店舗番号？日報 No？）か確認

次点：PDF 帳票をスタッフ名の正確な位置確認
  → basic_info_header の左右のオフセットを確認
```

## 📌 マスタ照合改善の可能性

### 現在のマスタ照合ロジック

```python
if pdf_staff in self.staff_master['staff_name'].values:

### 改善案（段階的）

```

#### 案 B: 名字のみで部分一致

```
現在：「原田」 → マスタ「原田菜々美」 → NO_MATCH

改善：「原田」 → マスタから「原田」で抽出 → もし 1 件なら MATCH

効果：
  推定 2～3 ページが改善
  
リスク：
  - 複数の「原田」がいる場合、曖昧になる
  - 確認：マスタに複数の「原田」はいるか？ → いない（原田菜々美のみ）
  
判定：リスク低い。可能
```

#### 案 C: 全正規化（全角→半角、カナなど）

```
効果：推定 5～10 ページが改善

リスク：高い
  - 誤同定のリスク増加
  - マスタの「漢字」に対して、PDF が「カタカナ」で来る可能性は低い
```

## ⚠️ bounds / prompt 改善の必要性

### 現在の設定

```python
# basic_info_header: (0, 14, 0, 100) → (top%, bottom%, left%, right%)
bounds = (0, 14, 0, 100)
zoom = 2

# Prompt
"Reporter's name (handwritten Japanese name)"
```

### 問題点

1. **「209」が拾われている** → bounds が隣フィールドに重なっている可能性
2. **87.1% が no_match** → Prompt が不十分か、bounds が間違っているか

### 改善案

#### 短期：bounds の確認

```
action: crop 画像を目視確認
  - P1: スタッフ名位置確認
  - P10: 「209」がどこから来ているか確認
  - P11: 唯一成功したページとの比較

確認項目：
  - 左側：「209」や別の数字が見える位置にあるか
  - 右側：スタッフ名の右端に余裕があるか
  - 上下：不要なテキスト（日報 No など）が含まれているか
```

#### 中期：Prompt の詳細化

```
案 1: スタッフ名フォーマットを明記

現在：
  "Reporter's name (handwritten Japanese name)"

改善：
  "Reporter's name (handwritten Japanese person name).
   - Only extract the personal name (full name or family name)
   - Do NOT extract numbers, IDs, or printed template values
   - Common names: (list 5-10 examples from staff_master)"

効果：
  - Vision API に「何が名前か」を明確化
  - 「209」などの数字の除外
```

案 2: 負のプロンプト

```
"Do NOT extract: numbers, printed values, dates, form IDs, tablet numbers"
```

#### 長期：bounds 微調整

```
action: 小規模テストで bounds を段階的に変更
  - left: 0 → 2（左側の数字フィールド除外）
  - right: 100 → 95（右側の余白除外）
  - height: 0-14% → 3-13%（上下の枠線除外）

小規模テスト：P1, P8, P9, P10 の 4 ページで検証
```

## 💡 重要な補足

### CSV 照合への影響は限定的

```
理由：
  - CSV は店舗 × 営業日 単位の行
  - スタッフ名は補助情報（スコア計算用の +2/-2）
  - CSV 検索キーは日付 + 店舗コード

現状：
  - スタッフ名が 87% 失敗しても、CSV 候補検索は成功
  - ただしスコアが低く、「複数候補」「要確認」判定が増える

改善効果：
  - match_rate が 54% → 56% 程度改善（スコア +2）
  - UI 表示の「スタッフ名」が正確になる
  - 将来のスタッフ単位照合に備える
```
