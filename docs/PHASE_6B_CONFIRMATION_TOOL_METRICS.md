# Phase 6B: 確認支援ツールとしての評価指標（評価軸の転換）

**作成日**: 2026-06-07
**目的**: `match_rate` 中心の評価をやめ、「**人間の確認を減らしつつ、絶対に誤確定しない**」という確認支援ツールの本質的価値で評価し直す。
**データ**: 既存の v3 / ハイブリッド照合結果のみ（Vision API 再実行なし、本体コード不変更）

---

## なぜ評価軸を変えるのか

`match_rate 54.4%` は技術指標であり、顧客が買う理由にならない。
照合支援ツールの命は **「一致と言ったものが本当に正しいか（誤確定0）」** と **「危険を取りこぼさないか（要確認捕捉）」**。

そこで主指標を以下へ転換した：

| 主指標 | 定義 | 意味 |
|---|---|---|
| **誤確定率 (false-confirm)** | 自動確定したが実FAXと食い違う件数 / 自動確定 | **最重要・目標0** |
| **要確認捕捉率** | 正しく拾った実差 / 実際の不一致総数 | 危険を見逃さない力 |
| **見逃し (false-negative)** | 実差なのにSKIP/確定した件数 | 取りこぼし |
| **自動確定率** | 自動確定 / 確認対象 | 人間の負荷をどれだけ消化したか |
| **要確認率** | 要確認 / 確認対象 | 人間に回す割合 |
| **作業削減見込み** | 自動確定 / 確認対象 | 確認作業の削減見込み |

---

## ツールの「判断」分類

各フィールドで、ツールは次の判断を下す：

| 判断 | 由来 | 意味 |
|---|---|---|
| **AUTO_CONFIRM（自動確定）** | match（Tier A/B のみ） | 「一致、確認不要」 |
| **FLAG（要確認）** | mismatch + uncertain + CSV空欄 | 「ここを確認して」 |
| **REFERENCE_MATCH（参考一致）** | Tier C の match | 一致しても**確定しない**（参考） |
| **SKIP（対象外）** | 値なし（空欄セル） | 確認対象なし |

---

## MVP評価表（Tier別 確定ポリシー）

| Tier | フィールド | 入力性質 | 確定ポリシー |
|---|---|---|---|
| **A** | AI（合計）, store_code | 印字数字 | **自動確定可** |
| **B** | 既存対応（HH-IO） | 印字寄り | **条件付き自動確定** |
| **B** | 新規オプション（GS-HG） | **正の字欄寄り** | **条件付き自動確定**。0疑義 / 正の字途中形 / uncertain / 空欄疑義は **review に落とす** |
| **C** | AU/AV/AY/AZ | 手書き正の字 | **自動確定しない**。matchしても **参考一致** 扱い |

→ **「誤確定0」を設計で担保**：最難関の Tier C は一切自動確定しない＝Tier C の誤確定は構造的にゼロ。

## 結果① ヘッドラインKPI（30ページ全項目）

| 指標 | v3 | ハイブリッド |
|---|---|---|
| 自動確定 (AUTO) | 37 | 37 |
| 要確認 (FLAG) | 66 | 70 |
| 参考一致 (REF, Tier C) | 12 | 12 |
| 対象外 (SKIP) | 5192 | 5188 |
| **確認対象 (AUTO+FLAG+REF)** | **115** | **119** |
| **自動確定率** | **32.2%** | 31.1% |
| **要確認率** | 57.4% | 58.8% |
| 参考一致率 | 10.4% | 10.1% |
| **作業削減見込み** | **32.2%** | 31.1% |

**読み方**: 比較可能な115項目のうち、約1/3を自動でクリアし、残りを人間に回す。ハイブリッドは要確認が+4件（後述の通り、AZの値を新たに表面化させた結果）。

## 結果② Tier別内訳（売れるコアの可視化）

| Tier | AUTO | FLAG | REF | SKIP | 自動確定率 |
|---|---|---|---|---|---|
| **A（AI 合計）** | 7 | 18 | 0 | 4 | 28.0% |
| **B（既存対応 HH-IO）** | **22** | 5 | 0 | 814 | **81.5%** ⭐ |
| **B（新規オプション GS-HG）** | 8 | 14 | 0 | 413 | 36.4% |
| **C（正の字 AU/AV/AY/AZ）** | 0 | 29 | 12 | 75 | 0.0%（設計通り） |
| Other（内訳欄） | 0 | 0 | 0 | 3886 | - |

**ハイライト**:
- **既存対応（Tier B）= 自動確定率 81.5%** がツールの稼ぎ頭。22件自動確定・要確認5件のみ。
- **Tier C は自動確定 0%（設計通り）**。29件を要確認、12件を参考一致として人間へ。誤確定リスクを構造的に排除。
- **AI（Tier A）は18件がFLAG**。AI抽出は100%成功する一方、Salesforce値と18件食い違う＝**ツールが実差を拾っている**（または AI→CSV列対応の要確認点）。→ 後述の調査候補。

## 結果③ 誤確定監査（目視検証済みサブセット） 🔴 最重要

人間が crop 目視した6項目を ground-truth として、ツールの判断を監査：

| ページ | 項目 | 実FAX | v3判断→監査 | hybrid判断→監査 |
|---|---|---|---|---|
| P01 | AZ | 正の字5 | SKIP → recall_gap | FLAG → **true_flag** |
| P06 | AZ | 集計30 | SKIP → recall_gap | FLAG → **true_flag** |
| P08 | AZ | 空欄 | SKIP → correct_skip | FLAG → false_flag |
| P10 | AZ | 不鮮明 | SKIP → correct_skip | FLAG → false_flag |
| P15 | AZ | タリー1 | FLAG → **true_flag** | FLAG → **true_flag** |
| P29 | HI | 空欄(40誤読) | FLAG → false_flag | FLAG → false_flag |

### 監査集計

| 指標 | v3 | ハイブリッド |
|---|---|---|
| **誤確定 (false-confirm)** | **0** | **0** ✅ 目標達成 |
| 真陽性FLAG (true-flag) | 1 | 3 |
| 偽陽性FLAG (false-flag) | 1 | 3 |
| 見逃し (missed) | 0 | 0 |
| 抽出見逃し (recall-gap) | 2 | 0 |
| 正しい空欄 (correct-skip) | 2 | 0 |
| **要確認捕捉率** | **100%** | **100%** |

**結論（検証サブセット）**:
- **誤確定 0件**（v3・hybrid 両方）— 不一致を一致と確定した事例はゼロ。
- **見逃し 0件・要確認捕捉率 100%** — 実差（P15 の FAX=1 vs SF=0）を正しくFLAG。
- **ハイブリッドの効果**: v3 が取りこぼしていた P01(5)/P06(30) を表面化（recall_gap → true_flag）。ただし空欄/不鮮明（P08/P10）もFLAG化し、偽陽性ノイズが+2。
- **トレードオフ**: ハイブリッドは「拾う力（recall）」が上がるが「ノイズ」も増える。誤確定0は崩さない。

⚠️ **正直な開示**: 検証サブセットは6項目と小規模。誤確定0は「現サンプルで0」であり統計的保証ではない。次段で検証サンプルを拡張する必要がある。

## 正直な限界開示：98%が SKIP（recall未知）

- 全5307項目のうち **5192件（98%）が SKIP（PDF値なし）**。
- 大半は「実際に空欄のセル」で正常。ただし一部に「書いてあるのに抽出が見逃した（false-negative）」が混在しうる。
- 現状、両者を区別できない＝**フォーム全体の recall（取りこぼし率）は未知**。
- これは商品の既知の限界として開示し、数ページを全項目手検証して recall を実測する計画を持つべき。

## ジオ様への説明文（そのまま使える言い換え）

> **本ツールは「自動確定ツール」ではなく「確認支援ツール」です。**
>
> 帳票とSalesforceを突き合わせ、**確認不要なものを自動で仕分け**し、**確認が必要なものだけをリスト化**します。
>
> - **既存対応の項目は約8割を自動確定**。担当者は残りの要確認だけ見ればよくなります。
> - **手書きの正の字欄（案件欄）は、あえて自動確定しません**。誤って「実績ゼロ」と確定する事故を構造的に防ぐためです。ここは必ず人の目で確認いただく前提です。
> - **検証した範囲では、誤確定（不一致を一致と誤って確定する事故）はゼロ**でした。実際の食い違い（FAXは1件、Salesforceは0件 等）も正しく拾い上げています。
> - テンプレートの印字を手書きと誤読する箇所（例: 電話追加の「40」）は、**自動で「要確認」に落とす**処理を入れています。
>
> 一致率の数字（◯%）ではなく、「**人の確認をどれだけ減らせるか**」「**危険な見落としをどれだけ防げるか**」で評価いただくのが、この道具の正しい使い方です。

| 優先 | アクション | 理由 |

| 🔴 | 検証サブセットの拡張（数ページを全項目目視） | 誤確定0・recall を統計的に裏付ける |
