## 失敗原因の仮説

### 主因：入力画像の低解像度

**ログ上の画像サイズ：179×252px**

この解像度では、手書き正の字（|，||，|||など）を正確に読むことは困難：
- 1本の線が数ピクセル単位
- 手書きのぶれやかすれが大きく見える
- AI合計欄だけを切り出しすぎており、周辺文脈が完全に失われている
- Vision が「どのセルを読むべきか」を判断できない可能性

### 副因：プロンプトの制約が強すぎる

- P11/P24/P28 が None になったのは、プロンプトの「厳密判定」が裏目に出ている
- わずかな曖昧さで「判定不能」に逃げるようになっている
- blank と 0 の区別が不安定

---

## 次フェーズ：V2.1高解像度テスト準備

### 改善方針

**プロンプトの大幅変更ではなく、まず入力画像を改善する**

改善内容：
1. **高解像度レンダリング**
   - 現状：プリンタ設定不明（179×252px）
   - 改善：300dpi または 400dpi でレンダリング
   - 期待：手書き文字が視認可能なサイズに

2. **Crop範囲を拡張**
   - パターンA：AI欄単体（高解像度化版）
   - パターンB：AU/AV/AY/AZ/AI を含む縦ブロック（行ラベル・文脈付き）
   - 目的：Vision が「どの行/列を読むか」を判断しやすくする

3. **Vision API再試行**
   - V2.1 では2種類の crop パターンで比較テスト
   - raw_response を必ず保存（なぜ失敗したかを後から分析）

### 実行予定

- **今回：** 高解像度 crop 画像生成 + スクリプト準備（Vision API呼び出しは止める）
- **次回：** Vision API 再実行 + 結果評価
