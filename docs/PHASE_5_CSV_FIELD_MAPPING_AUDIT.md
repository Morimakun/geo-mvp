# Phase 5.2.5: Salesforce CSV フィールドマッピング監査

**作成日**: 2026-06-11  
**状態**: CSV全283列棚卸し完了・重大な対応ズレを確認  
**結論**: PDF「AI合計欄」がSalesforce CSVの列に正しく対応していない可能性が極めて高い

---

## 目的

Phase 2で、CSV列35「紹介総数」がPDF帳票の「AI合計欄」と異なる項目である可能性が判明しました。

本Phase では、Salesforce CSV全283列の中から、PDF「AI合計欄」に対応する列を客観的なデータ一致率で特定します。

---

## なぜCSV列対応を確認する必要があるか

```
従来の精度評価:
  PDF目視AI合計欄 vs v3/V2.2/CSV値 を比較

問題:
  もし CSV がPDF AI合計欄と違う列を出力していれば、
  「OCR精度が低い」のではなく「対応関係が誤り」
  → 精度改善の方向が完全に間違う
```

**したがって、精度改善に進む前に、PDF項目とCSV列の対応を確定することが最優先。**

## 🚨 **可能性の整理**

### 可能性1：列35が誤対応だった（確認済み）

✅ **確認**: CSV列35「紹介総数」の一致率は18.75%。これはPDF「AI合計欄」ではない。

### 可能性2：PDF「AI合計欄」に対応する列が別にある

⚠️ **結果**: 全283列中、最高一致率は31.2%（複数列で同率）。これは「偶然の一致」レベル。

**解釈**: 
```
統計的に、ランダム一致の期待値 ≈ 6-10%（16ページ中数ページの一致）
実際の最高 31.2% は、確かに高いが、100%や95%ではない

つまり、CSV列と PDF「AI合計欄」の対応が、根本的に確立されていない可能性
```

### 可能性3：CSVにPDF「AI合計欄」が出力されていない

🔴 **最有力**

```
Salesforce 側で、PDF帳票上の「AI合計欄」という項目が、
CSV出力の対象外かもしれない。

つまり、「CSVに無い項目」を「CSVで探す」ことになっている。
```

### 可能性4：PDFページとCSV行の対応がズレている

⚠️ **可能性**

```
例：
  PDF P1 = CSV行1 と想定して比較していたが、
  実際には PDF P1 = CSV行2 かもしれない

この場合、全列の一致率が均等に低くなる（現象と一致）
```
