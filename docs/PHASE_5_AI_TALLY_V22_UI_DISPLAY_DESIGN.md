**作成日：** 2026-06-08  
**対象：** AI合計欄V2.2判定の画面表示設計（参考判定・確認支援目的）  
**位置づけ：** 表示設計のみ。app.py直接編集は Phase 5 Step 4 以降

## 1. UI表示の目的

**V2.2判定をUIに表示する狙い：**

1. **確認範囲の明示**
   - 「自動確定候補」：見なくてもOK（が、初期は確認推奨）
   - 「要確認」：ここだけ見れば良い（範囲を53%削減）

2. **重大誤りの未然防止**
   - P14型：v3大誤読（34→3）を機械が先に検出
   - P16型：悪化を検知し review へ強制
   - confidence低：無条件に review へ

3. **確認支援ツールとしての価値提供**
   - 「自動なのにここまで考えてくれるのか」という信頼醸成
   - PDF読取の正確さを可視化（V2.2推定値・理由の提示）
   - OCR補正候補として、改善実績を示す

---

## 2. 表示対象・非対象

### 表示対象

すべての30ページについて、以下を表示する：

1. **自動確定候補（auto_confirm_candidate==true）**
2. **要確認（review_required==true かつ confidence!=low）**
3. **低信頼度（confidence==low）**
4. **OCR補正候補（v22!=v3 かつ v22==csv）**

### 表示しない対象

- ❌ v3値（参考値だが、初期段階では混乱を招く）
- ❌ review_reason 詳細（要確認ページのみ簡潔に表示）
- ❌ 内訳（AU/AV/AY/AZ）はまだ併用しないため非表示
- ❌ CSV列35の値（UI上は「Salesforce AI値」として抽象化）
- ❌ APIレスポンス全文（display_message のみ）

## 3. 表示方法（4分類別）

### A. 自動確定候補（Auto Confirm Candidate）

**条件：**
- `auto_confirm_candidate == true`
- `review_required == false`

**特徴：**
- PDF AI合計とCSV AIが完全一致
- confidence が medium 以上
- target_cell_found = true

**UI表示例：**

```
✅ 自動確定候補
┌────────────────────────────────────────┐
│ PDF AI合計：5                          │
│ Salesforce AI値：5                     │
│ → 完全に一致しています。               │
│    確認をスキップ可能な候補です。      │
└────────────────────────────────────────┘

推奨アクション：[スキップ] [確認する]
```

**色・アイコン案：**
- 背景：緑系（#D4EDDA）
- アイコン：✅ または 🟢
- テキスト色：濃緑

**表示優先度：** 低（スキップ可能なため、下位）

---

### B. 要確認（Review Required - Standard）

**条件：**
- `review_required == true`
- `confidence != "low"`（低信頼度は別カテゴリ）

**特徴：**
- PDF AI合計とCSV AIに差分あり
- 複数の理由で確認が必要
- 人間判断が必要

**UI表示例：**

```
⚠️ 要確認
┌────────────────────────────────────────┐
│ PDF AI合計：2                          │
│ Salesforce AI値：11                    │
│ 差分：+9                               │
│                                        │
│ 理由：                                 │
│  • v22値とCSVが不一致                  │
│  • Salesforce更新タイミング差の可能性  │
│                                        │
│ → 確認して値を確定してください。       │
└────────────────────────────────────────┘

推奨アクション：[確認して確定] [修正]
```

**色・アイコン案：**
- 背景：黄系（#FFF3CD）
- アイコン：⚠️ または 🟡
- テキスト色：濃黄

**表示優先度：** 中（必ず確認すべき）

---

### C. 低信頼度（Low Confidence）

**条件：**
- `confidence == "low"`

**特徴：**
- AIの推定精度が低い
- マスク領域の影響がある可能性
- 複合問題を検出
- 無条件に確認が必要

**UI表示例：**

```
🔶 低信頼度（強制確認）
┌────────────────────────────────────────┐
│ PDF AI合計：2                          │
│ Salesforce AI値：2                     │
│                                        │
│ 信頼度：低                             │
│ AIの確信度が低いため、必ず確認が      │
│ 必要です。                             │
│                                        │
│ 理由：v3との大差・マスク領域の影響     │
└────────────────────────────────────────┘

推奨アクション：[強制確認必須] [修正]
```

**色・アイコン案：**
- 背景：オレンジ系（#FFE5CC）
- アイコン：🔶 または 🟠
- テキスト色：濃オレンジ

**表示優先度：** 高（最優先）

---

### D. OCR補正候補（OCR Correction Candidate）

**条件：**
- `v22_value != v3_value`
- `v22_value == csv_value`

**特徴：**
- v3の誤読をV2.2が補正
- 補正後の値がCSVと一致
- 大きな改善の可能性
- 初期は確認推奨（改善の実績を確認するため）

**UI表示例：**

```
🔄 OCR補正候補
┌────────────────────────────────────────┐
│ 旧読取値（v3）：34                    │
│ 新読取値（v22）：3                    │
│ Salesforce AI値：3                    │
│                                        │
│ → 読取の改善が検出されました。         │
│    V2.2により大幅に補正された可能性。  │
│    初回導入時はサンプル確認推奨。      │
└────────────────────────────────────────┘

推奨アクション：[サンプル確認] [確認済み]
```

**色・アイコン案：**
- 背景：水色系（#D1ECF1）
- アイコン：🔄 または 🔵
- テキスト色：濃青

**表示優先度：** 中〜低（改善実績は有用だが、自動確定候補に優先度を譲る）

## 6. 表示優先順位

**UI上での優先順位（上から順に表示）：**

1. **🔶 低信頼度** - 最優先。必ず目に入る位置に
2. **⚠️ 要確認** - 次点。見逃さない位置
3. **🔄 OCR補正候補** - 参考情報。学習価値
4. **✅ 自動確定候補** - 最下位。スキップ可能

**複合の場合：**
- 低信頼度が存在すれば、最上位に
- OCR補正候補 + 自動確定は並記（但し自動確定を優先表示）

```

追加列:
  v22_ai_value                  # V2.2推定値
  v22_ai_value_confidence       # V2.2信頼度
  v22_auto_confirm              # auto_confirm_candidate
  v22_review_required           # review_required
  v22_review_reason             # 要確認理由（複数は;区切り）
  v22_classification            # ocr_correction/low_confidence等
  v22_suggested_action          # skip/confirm/force_review
```

## 10. UI実装前の重要な注意点

### 10.1 V2.2は参考判定・確認支援ツール

❌ **やってはいけないこと：**
- V2.2を「本判定」として表示する
- match_rate を前面化する
- 「AI自動確定」と謳う

✅ **やるべきこと：**
- 「V2.2による推定」として表示
- 「確認の参考」と明記
- 確認支援ツール として位置づける

### 10.2 初期導入では自動確定でも確認推奨

```
初期導入フェーズ（0-2週間）：
  ✅ auto_confirm であっても、
     サンプルは確認推奨（学習目的）
  
  スキップは概ね月1回程度の
  抜き打ち検査にとどめる

本格運用フェーズ（3週間以降）：
  ✅ auto_confirm は本当にスキップ可
  
  ただし定期的（月1回）に
  スキップ実績をレビュー
```

### 10.3 confidence low は絶対に自動確定しない

```
confidence == low の場合：
  → [強制確認必須] を表示
  → スキップボタンを提示しない
  → 必ず人間判断を強制
```

### 10.4 review_required は必ず確認

```
review_required == true の場合：
  → [確認して確定] をメイン
  → [スキップ] は提示しない
  → CSV不一致は特に注意
```

### 10.5 OCR補正候補は初期確認推奨

```
OCR補正候補（v22≠v3 & v22==csv）:
  → 初期導入では [サンプル確認] 推奨
  → 改善パターンの学習に有用
  → 信頼醸成のチャンス
```

### 10.6 CSV不一致は自動確定しない

```
v22 != csv の場合：
  → 無条件に review_required へ
  → auto_confirm には含めない
  → 誤確定リスク排除が最優先
```
