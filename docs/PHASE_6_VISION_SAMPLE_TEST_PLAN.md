## 1. 試験の目的

1. 新帳票でAI合計欄（紹介）が既存プロンプト方式で読めるかの初見確認
2. 新項目（帳票区分・提出区分・スタッフID・店舗コード）が画像から判読できるかの確認
3. 旧帳票ページが従来どおり読めることの確認
4. 6/27不一致店の帳票原本値が「転記シート」と「CSV」のどちらと一致するかの確認
5. 最低品質ページでの挙動（エラー/誤読/正直な「読めない」）の確認

※ 注意：今回データは**お声がけ総数が全店全日0**のため、CZ合計欄の実質的な精度検証はできない（0が読めることの確認のみ）。

## 4. 実行方法（GO後）

- 既存 `extractor.py` の関数を**変更せずそのまま**呼び出す一時スクリプト（`outputs/phase6_temp/` 配置・コミットしない）で、対象ページのみをPDFから切り出して渡す
- API実行は**最大5ページ・各1回**（リトライしない）。コスト概算：Vision入力5画像＋プロンプト（軽微）
- 新項目（区分・スタッフID等）は既存プロンプトでは返らない想定のため、**未抽出になることの確認**が成果。新プロンプトの試作はまだ行わない

## 5. 合否の見方（この試験の判定基準）

1. P58でAI合計欄=1が取れる → 新帳票でも合計欄抽出の見込みあり
2. P8で区分・数値が判読可能画質である → イベント帳票対応の実現性確認
3. P10が従来相当に読める → 旧帳票互換の確認
4. P11/P10の原本値確認 → 不一致3件の原因切り分け材料（片山様への確認の裏付け）
5. P30で誤読せず「読めない」と判定できる → エラー処理設計の材料
