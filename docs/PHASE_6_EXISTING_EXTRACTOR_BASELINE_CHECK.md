## 1. 既存抽出が返す項目（現状）

`extractor.py` は全ページ画像＋プロンプト方式（固定座標クロップは本番経路では未使用）で、以下を返す：

```
date, store, name, data_no, tab_no, count, total, notes,
left_totals, right_totals
```

- `left_totals` / `right_totals`：AI/CZ合計欄相当の左右合計群
- プロンプトの文言・例示は**旧帳票（2026/4/1版）レイアウト前提**

## 2. 新帳票に対して既存抽出をそのまま使った場合に足りない項目

| 新帳票項目 | 既存出力 | 状態 |
|-----------|---------|------|
| 帳票区分（1店舗/2イベント） | なし | **未対応（新規）** — 照合キーに必須 |
| 提出区分（1初回/2再送変更あり/3再送変更なし） | なし | **未対応（新規）** |
| 店舗コード（AU1K＋マス） | なし（storeは店名文字列のみ） | **未対応（新規）** — CSV col1との直結キー |
| スタッフID（7桁手書き） | なし（nameは氏名のみ） | **未対応（新規）** |
| 店舗活動無しチェック（通し番号102） | なし | **未対応（新規）** |
| 帳票バージョン判定（新旧） | なし | **未対応（新規）** — 移行期は日単位で新旧が入れ替わるため必須 |
| 通し番号1〜104の個別項目 | 対象外（合計のみ） | 初期版スコープ外を維持 |

## 3. AI/CZ合計欄抽出の新帳票適用可否（仮説・未検証）

- 新帳票でも【案件】合計（通し番号5）の紹介/声掛の構造は旧帳票と同型 → **プロンプト方式なら流用できる可能性がある**
- ただし (1) 通し番号が付いたこと、(2) 物理位置が変わったこと、(3) プロンプト例示が旧レイアウト前提であることから、**そのまま高精度が出るとは想定しない**
- 旧帳票（66ページ中17枚）に対しては既存抽出がそのまま適用できる見込み（レイアウト同一のため）。ただし精度判定は未実施
