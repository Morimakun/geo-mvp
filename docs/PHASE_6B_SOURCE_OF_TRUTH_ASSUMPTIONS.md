```

CZ  = DL + DM + DP + DQ  （4つの別ブロック項目の合計）
```

**0-index / 1-index変換：** `csv_column_number - 1 = iloc位置` → **正しいことを実データで実証済み**

### PDF側の定義

```
合計欄（合計（数字で記入）行・紹介列）
  ├─ 左ブロック（アルファベット欄）
  │  ├─ AU行・AV行・AY行・AZ行（内訳）
  │  └─ AI行（合計）
  └─ 右ブロック（額対応）
     ├─ 0 / 40 / 0 / 15 / 10 / 20... （テンプレート値）
     └─ 下の空欄（使わない）
```

**AI は左ブロック合計セルから直接読取。** 計算ではなく手書き値の読取。

### 右ブロック値（AI/CZと無関係）

```
右側ブロックの数値：0, 40, 0, 15, 10, 20, 10, 10...
  → これらは AI/CZ の合計対象ではない
  → テンプレート値またはリファレンス値
  → 右ブロック直下の合計欄は使わない空欄
```

## 4. 差分が出た場合の原因分類（新規体系）

AI合計欄など、差分が出た場合は以下 **A～G** で分類（マッピング誤りは対象外）：

| 原因 | 説明 | 対処 |
|------|------|------|
| **A. PDF読取位置の問題** | Vision API のクロップ領域が AI 合計セルを正しく取得していない | クロップ座標の見直し、Vision プロンプトの改善 |
| **B. PDF手書き値の読取ミス** | AI合計セルの数字を正しく読み取れていない（OCR誤認識） | Vision プロンプトの精度向上、不確実フラグの活用 |
| **C. 内訳項目の抽出不足** | AU/AV/AY/AZ が null/uncertain で、合計との検証ができない | 内訳項目の抽出精度向上。blank vs 0 の区別改善 |
| **D. PDFとCSVの実差分** | PDF も CSV も正しく読取・抽出されているが、業務実績として差分がある | 記録漏れ・入力誤差・更新遅延など。要目視確認 |
| **E. 比較ロジックの問題** | PDF側/CSV側は正しいが、比較時に誤処理（型変換・スキップ誤り等） | reconciliation_phase1.py のロジック検証（読取のみ） |
| **F. 手書きルール例外** | 正の字の途中形（書き順判定が曖昧）など、Vision API が正しく判定できない例外 | uncertain フラグの運用改善。Tier C として要確認化 |
| **G. 要目視確認** | 上記どれにも当てはまらない、または複合的な問題 | 原紙確認・Salesforce確認・ユーザー確認 |

**旧の疑問（AI定義違い、右ブロック混入など）：対象外。**

## 7. ジオ様確認が必要な場合の条件

| 確認項目 | 必要な場合 | 不要な場合 |
|---------|---------|---------|
| **定義確認（AI = AU+AV+AY+AZ？）** | — | ✅ 不要（確定済み） |
| **PDF原紙のAI欄値確認** | Tier C（要確認）でP14=34, P11=20 など | Tier A/B は確認不要 |
| **CSV列35の集計範囲・タイミング** | D. 実差分の可能性が高い場合 | A/B/C 確定できた場合は不要 |
| **内訳項目（AU/AV/AY/AZ）の精度** | C. 内訳抽出不足が判明した場合 | Vision プロンプト改善で解決なら不要 |
| **手書きルール例外** | F. 正の字途中形など汎用化できない例外 | ルール化・uncertain フラグで対応できれば不要 |

**基本方針：** "提供資料を疑う" 確認は終了。以後は "読取値・抽出精度・実差分" の三者択一で分類。
