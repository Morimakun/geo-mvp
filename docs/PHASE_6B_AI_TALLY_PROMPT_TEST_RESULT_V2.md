## 1. テスト背景

### 1.1 問題の発見

ユーザーが実 PDF から確認した結果、Vision API が正の字を数字として誤認識していることが判明：

| ページ | v3誤読値 | ユーザー目視解釈 | 原因 | 読取位置 |
|--------|---------|-----------------|------|---------|
| P14 | 34 | 3 | 正の字（3画）をアラビア数字と誤読 | **AI合計行** |
| P11 | 20 | 2 | 正の字（2画）をアラビア数字と誤読 | AI合計行 |
| P24 | 7 | 2 | 正の字（2画）をアラビア数字と誤読 | AI合計行 |
| P12 | 0 | 1 | 正の字（1画）を「0」と誤読 | AI合計行 |
| P28 | 0 | 0 | ✅ 正確（空欄） | AI合計行 |

**重要な確定事項：**
- P14 の Vision=34 は非接列混入ではなく、AI合計行の手書き正の字誤読
- クロップ位置は正確（AI欄のみ、非接列は含まれていない）
- 主因：Vision API が正の字/崩れ字をアラビア数字として解釈

### 1.2 改善方針

Vision プロンプトを改善して、以下を明示的に指示：

```
【重要】正の字とアラビア数字を区別してください：

記入形式A：アラビア数字（0, 1, 2, 3, 4, 5, ..., 10, 20, 34）
→ その数字をそのまま返す

記入形式B：正の字（書き順に沿った段階的な描き方）
→ 正の字の書き順に沿って、1～5画のどの段階まで書かれているかを判定する
  （アラビア数字として解釈しない）

記入形式C：空欄
→ 「0」または「blank」
```

## 8. 重要な注釈（正の字ルール確認）

### 正の字の書き順に沿った判定

```
【描き進まれた段階での判定】

1画：「一」（横棒のみ）
  ┌─────┐
  │ ─── │
  └─────┘

2画：「十」T字形（横棒＋縦棒）
  ┌─────┐
  │  |  │
  │ ─┼─ │
  │  |  │
  └─────┘
  （見た目が「十」に見えても、横棒＋縦棒の2本だけなら2画）

3画：「十」＋中段横棒（十字形＋中段）
  ┌─────┐
  │  |  │
  │ ─┼─ │
  │  |  │
  │ ─┼  │
  └─────┘

4画：3画＋左側縦棒
  ┌─────┐
  │ | | │
  │ ─┼─ │
  │ | | │
  │ ─┼  │
  └─────┘

5画：完成した「正」
  ┌─────┐
  │ | | │
  │ ─┼─ │
  │ | | │
  │ ─┼─ │
  └─────┘
```

**重要な注釈：**
- 十字形に見えても、横棒＋縦棒の2本だけで完成していなければ2画です
- 十字形＋中段の横棒で初めて3画になります
- 見た目の漢字名ではなく、書き順の進行段階で判定します
