## 1. テスト背景

### 1.1 問題の発見

ジオ様原紙確認により、Vision API が正の字を数字として誤認識していることが判明：

| ページ | 誤読値 | 正解値 | 原因 |
|--------|--------|--------|------|
| P14 | 34 | 3 | 正の字（画数=3）を「34」と誤読 |
| P11 | 20 | 2 | 正の字（画数=2）を「20」と誤読 |
| P24 | 7 | 2 | 正の字（画数=2）を「7」と誤読 |
| P12 | 0 | 1 | 正の字（画数=1）を「0」と誤読 |
| P28 | 0 | 0 | ✅ 正確（空欄） |

### 1.2 改善方針

Vision プロンプトを改善して、以下を明示的に指示：

```
【重要】正の字とアラビア数字を区別してください：

記入形式A：アラビア数字（0, 1, 2, 3, 4, 5, ..., 10, 20, 34）
→ その数字をそのまま返す

記入形式B：正の字（書き順に沿った段階的な描き方）
→ 正の字の書き順に沿って、1～5画のどの段階まで書かれているかを判定する（アラビア数字として解釈しない）

記入形式C：空欄
→ 「0」または「blank」
```

## 9. 技術詳細

### 改善プロンプトの効果

**Key Changes:**

1. **正の字の定義を明示**
   - 正の字は数字ではなく、書き順に沿った描き進み段階として解釈
   - 1～5画のどの段階まで書かれているかを判定して返す

2. **記入形式を3分類**
   - A：アラビア数字 → そのまま返す
   - B：正の字 → 書き順に沿った1～5画判定を返す
   - C：空欄 → 「0」または「blank」

3. **禁止事項を明示**
   - 複数の線を桁として読まない
   - 罫線を数えない
   - 右側ブロック読まない

**結果：**
- v3 の誤読パターン（「34」「20」「7」）がすべて消滅
- 空欄の「0」を正確に判定
- 「正の字=書き順に沿った1～5画判定」という明確なルールの有効性確認
