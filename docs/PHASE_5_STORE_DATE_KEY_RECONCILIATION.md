## 📋 Executive Summary

### 🔴 重大な発見：不一致の原因は AI読取精度ではなく「照合キー」の誤り

```
従来の評価:
  P16:  PDF目視=9 vs CSV=11 → 「差=-2」「CSVが間違い」
  P30:  PDF目視=2 vs CSV=1  → 「差=+1」「CSVが間違い」

原因: PDFページ番号とCSV行番号を単純対応させていた
      ページP16=行16 ではなく、店舗×日付キーで正しい行を特定すべきだった
```

## 🎯 なぜ「店舗×日付キー」が必須か

### 従来のアプローチの問題

```
ページP16 = CSV行16 と仮定
  ↓
PDFページ16に「熊取 5/18」の帳票がある
  ↓
CSVの行16を見ると「ニトリモール枚方 5/18」だった
  ↓
PDF目視=9 vs CSV=11 で不一致扱い
  ↓
「SalesforceのCSV入力が間違っている」と判定

❌ しかし実は、CSV行16はまったく別の店舗
```

### 正しいアプローチ

```
PDF帳票から「店舗名（取扱コード）と日付」を読み取る
  ↓
「熊取（AU1KC310039）× 2026/05/18」をキーにCSVを検索
  ↓
CSVの行27がこのキーと一致
  ↓
PDF目視=9 vs CSV行27=9 で完全一致
  ↓
✅ 「Salesforce入力は正確」と判定
```

## 🔑 PDFページ ↔ CSV行の対応キー

### 確定事実

**対応キー：** `取扱コード（列281）× 日付（列283）`

### なぜこのキーか

1. **各PDFページのFAXヘッダーに「店舗名」と「日付」が印字されている**
2. **店舗マスター（店舗名　スタッフ名.xlsx）で店舗名↔取扱コードが1:1対応**
3. **CSVの列281（取扱コード）と列283（日付）で一意にレコード特定可能**
4. **PDFはFAX着信順（= CSV行順ではない）のため、ページ番号との対応なし**

## 💡 これまでの低精度評価がなぜ崩れたか

### Phase 1-2.5 で報告された数字

| 評価対象 | 精度 |
|---------|------|
| v3 | 50% |
| V2.2 | 40% |
| CSV | 30% |
| 3ソース一致Tier | 37.5% |

### 現実

```
P16:  「CSV=11 vs PDF目視=9」
      → 実は P16=ニトリモール枚方（CSV行16）
      → 正しい行：熊取5/18=CSV行27=9
      → ページ順とCSV行順が違うために発生した誤検出

P30:  「CSV=1 vs PDF目視=2」
      → 実は P30=複数行ある日付（CSV行30）
      → 正しい行：JR神戸北5/18=CSV行31=2
      → 同じく行ズレによる誤検出
```

### 原因

```
【ページ番号 = CSV行番号】という単純仮定の崩壊

PDFはFAX着信順（到着順）で30ページ連番
CSVは店舗コード順（Salesforce内部順）で43行記録

この2つの順序は全く異なる
  ↓
ページP1 ≠ CSV行1
ページP16 ≠ CSV行16
  ↓
別店舗・別日付のCSV行と比較されていた
  ↓
評価精度が汚染された
```
