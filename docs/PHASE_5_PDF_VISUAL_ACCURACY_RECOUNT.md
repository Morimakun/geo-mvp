# PHASE 5: PDF目視正解を基準とした精度評価の再集計

---

## ⚠️ **重要な注意事項**

**本レポートはPDF目視正解を基準にした30ページ限定の検証結果であり、全帳票・全店舗での保証精度ではありません。**

- サンプル数: 30ページ（限定的）
- 対象: AI合計欄のみ
- 目的: 評価軸の転換（CSV基準 → PDF目視基準）と現在の危険性の把握
- 本番導入: 追加の正解データ（100ページ以上）による再評価が必須

---

## 目的

これまで、AI合計欄の精度評価はCSV（Salesforce）の値を基準に行われていました。しかし、目視確認の結果、CSVの数値とPDFの実際の視認値に大きな乖離があることが判明しました。

**本レポートは、評価軸をCSV基準からPDF目視基準に変更し、以下を実施します：**

1. PDF目視正解を確定値として、AI合計欄の精度を再評価
2. V2.2、v3、CSVの各結果をPDF目視正解と比較
3. auto_confirm_candidate の正確性と危険誤確定の検出
4. review_required フラグの捕捉率を確認

---

## 対象ページ・フィールド

- **ページ**: P1～P30（全30ページ）
- **フィールド**: AI合計欄（CZ列ではなく、手書き帳票のAI自動集計欄）
- **確定値**: P14=3, P16=9, P30=2（PDF人間再確認済み）

## デモでの説明方針

### 主要なメッセージ

1. **精度評価の軸を変更した意図**
   - CSV基準では実態を反映していない
   - PDF目視（人間による確認）を絶対基準とすることで、本来の問題を可視化

2. **v3 の性能が期待を上回る**
   - v3: 50% 正解率
   - V2.2: 40% 正解率
   - CSV: 30% 正解率
   - ⇒ v3 の導入が改善効果あり

3. **危険誤確定の実例**
   - P30 などの「確認済みページ」でも誤確定が発生
   - auto_confirm_candidate の現在の基準では不十分
   - 本番環境での運用には多くの手動確認が必要

4. **review_required の精度改善の可能性**
   - 現在は 44% の捕捉率（不十分）
   - 「差分の大きさ」を追加ルール化すれば改善可能

5. **次のステップ**
   - v3 の「正解」パターンを学習
   - auto_confirm の判定基準を V2.2 ベースから v3 ベースへ
   - 人間確認の優先度を「差分の大きさ」で自動ランク付け

## 危険誤確定が発生した理由

### 構造的な問題

1. **CSV 一致を正解扱いしていた**
   - これまでのロジック: 「V2.2値 = CSV値 → 自動確定候補」
   - しかし: PDF目視では 9 / 17 のページで不一致
   - 理由: Salesforce CSV のデータ入力誤りや、日付境界のズレ、複数版管理の曖昧さ
   - 結果: CSV 一致だけで確定すると 58% の危険誤確定

2. **V2.2 はAI補助レイヤーだが、PDF 目視ベースでは v3 より低い**
   - V2.2 の設計意図: v3 の誤読を補正する
   - 期待値: V2.2 ≥ v3 の精度
   - 現実: V2.2 40% < v3 50%
   - 理由: P16 / P30 など、V2.2 が大きく誤認するケースが散在

3. **P30 のようなケースの存在**
   - V2.2 = 1（CSV と一致）
   - PDF 目視 = 2（実際の値）
   - confidence = high, auto_confirm_candidate = true
   - にもかかわらず誤確定になる
   - これは「信頼度」「CSV 一致」だけでは不十分な証拠

4. **自動化の限界**
   - 機械判定で「確実」と思ってもPDF実物を見ると異なる
   - 特に手書き、FAX品質不良の場合、AI の正確性は低い
   - P14 の v3=34 のような計算エラーも存在
   - すべての不確実性を「信頼度」一つでは表現できない

### 誤確定リスクの定量化

| 指標 | 値 | 意味 |
|-----|-----|------|
| auto_confirm=true | 17 ページ | 自動確定候補のつもりが... |
| 実は誤り | 10 ページ | 58.82% が不正確 |
| 危険誤確定率 | 58.82% | **本番利用不可レベル** |

## 重要な注意事項

1. **PDF目視正解の状況**
   - P14=3, P16=9, P30=2（確認済み）
   - P19=4, P29=2（実際にはデータあり）
   - ブランク期待と異なるため、指示確認が必要な場合あり

2. **v3 の外れ値**
   - P14 で v3=34 など、計算エラーの可能性
   - v3 の信頼度が100%ではない点に注意

3. **本番環境への影響**
   - 現在の auto_confirm_candidate では 58% が危険状態
   - デプロイ前に検証環境での full-cycle test 必須
   - review_required フラグも誤検出が多い

4. **CSV（Salesforce）の同期**
   - CSV と V2.2 がほぼ同じ誤りを共有
   - Salesforce 側の集計ロジックも見直し可能性あり
